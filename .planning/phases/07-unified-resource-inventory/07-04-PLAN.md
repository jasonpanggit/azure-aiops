<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider payload -> ResourceObservation | Untrusted provider content is retained losslessly inside inventory |
| ResourceObservation -> Fabric/Delta/Parquet table | Opaque payload crosses into durable OneLake/Fabric source-of-truth storage |
| Fabric-backed inventory -> API response | Internal raw payload must not leak to clients through compatibility or new routes |
| family registry -> publication/read selection | Registry drives which tables are written/read and must prevent collisions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-13 | Information Disclosure | retained provider payload | high | mitigate | Tasks 1 and 2 require payload to be internal-only and tests that API responses do not expose it |
| T-07-14 | Tampering | payload passthrough | medium | mitigate | Task 2 requires mutation-isolation tests so callers cannot alter stored observations by mutating returned payloads |
| T-07-15 | Tampering | Fabric payload serialization | high | mitigate | Task 1 uses canonical JSON encoding with decode tests over Parquet so heterogeneous provider shapes cannot corrupt columns silently |
| T-07-16 | Denial of Service | unbounded payload size | medium | mitigate | Task 1 records table size impact in the summary; do not truncate because truncation violates D-08 |
| T-07-17 | Tampering | duplicate family/table registration | medium | mitigate | Task 3 rejects duplicate logical dataset aliases and duplicate Fabric table names |

No package-manager installs occur in this plan, so no package-legitimacy gate applies.
