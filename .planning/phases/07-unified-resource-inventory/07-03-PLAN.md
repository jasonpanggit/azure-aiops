<objective>
Invert ownership: move inventory acquisition, normalization, retention, source status, and publication out of the Hermes connector and into the inventory domain, so an inventory refresh no longer requires a semantic-graph sync run.

Purpose: D-01 and D-02, and the core of INV-07. This removes the coupling behind the current `provider_unavailable` 503. Per D-06 nothing observable changes: dataset names and row shapes stay byte-identical — only the owner changes.

Output: an inventory pipeline module that acquires, normalizes, retains, statuses, and publishes on its own; Hermes reduced to a caller that no longer carries inventory on its graph.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Azure Resource Graph -> inventory pipeline | Untrusted provider payloads enter the inventory domain directly for the first time |
| Log Analytics ConfigurationData -> inventory pipeline | Untrusted workspace query results enter the inventory domain directly |
| inventory pipeline -> published generation | The pipeline becomes a second writer against the shared generation root |
| server-owned workspace mappings -> logs acquisition | Workspace selection must remain server-owned, never caller-supplied |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08 | Tampering | inventory publication vs Hermes publication | high | mitigate | Task 1 requires a both-orders test proving neither publisher drops the other's datasets from the active generation |
| T-07-09 | Spoofing | workspace resolution in the relocated logs acquisition | high | mitigate | Move workspace resolution unchanged — only validated server-owned connection mappings are queried; add a test that a caller-supplied workspace id is not honoured |
| T-07-10 | Information Disclosure | relocated ARG/Logs acquisition | medium | mitigate | Preserve the existing connection-context and requested-scope stamping on every row so scope enforcement downstream keeps its inputs; assert scope attributes survive the move |
| T-07-11 | Repudiation | source status and evidence after relocation | medium | mitigate | Characterization suite asserts evidence engine/table/observed_at/query_version remain populated on relocated rows |
| T-07-12 | Denial of Service | two writers against one generation root | medium | mitigate | Inventory publication reuses the existing run lock or an equivalent, so concurrent Hermes sync and inventory refresh cannot interleave a partial generation |

No package-manager installs occur in this plan, so no package-legitimacy gate applies.
