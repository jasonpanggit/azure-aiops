</objective>

  <action>
    Do this **before** the tracer. Task 1b introduces a second publisher against the generation root; this task makes that safe first, so the hazard mitigation is not competing for budget with a tracer that must go green.

    Publication must go through the single existing immutable-generation path — do not add a second write path. Once the OS datasets are published by the inventory pipeline while Hermes still publishes the rest of the estate, **two publishers share one generation root and one hash-state file, and that shared state is the real hazard.**

    Read `publish()` in the neutral store before changing anything. It loads `old_hashes` for *all* datasets across both domains, builds `new_hashes` containing only the datasets it was asked to write, then computes removals as `set(old_hashes) - set(new_hashes)` and finally overwrites the hash file wholesale. A partial publish therefore (a) marks every `entities/*`, `relationships/*`, and `situations/*` dataset as changed-because-removed in the manifest, and (b) destroys the baseline the next Hermes sync diffs against — silently breaking incremental change detection, which `tests/test_incremental_sync.py` exists to protect.

    Fix this explicitly. Either make publication **merge-not-replace** for both generation contents and hash state — datasets the caller did not ask to write are carried forward from the active generation and their hashes retained rather than treated as removed — or namespace publication per domain with independent hash state and an independent pointer per domain. Take one approach; do not mix them. Record which approach you took and why in the plan summary; task 3's sync-triggers-refresh decision is constrained by it.

    Note also that `ontology/ontology` is written unconditionally by the graph publish path. A partial publish must neither drop it nor duplicate it.

    No inventory pipeline exists yet at this point, and none is needed: drive these tests with the existing Hermes publisher plus a synthetic partial publish that writes only a subset of datasets. That is sufficient to reproduce both defects.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Azure Resource Graph -> inventory pipeline | Untrusted provider payloads enter the inventory domain directly for the first time |
| Log Analytics ConfigurationData -> inventory pipeline | Untrusted workspace query results enter the inventory domain directly |
| inventory pipeline -> published generation | The pipeline becomes a second writer against the shared generation root |
| server-owned workspace mappings -> logs acquisition | Workspace selection must remain server-owned, never caller-supplied |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08 | Tampering | inventory publication vs Hermes publication | high | mitigate | Task 1a requires merge-not-replace (or per-domain namespacing) for generation contents AND hash state, a both-orders test proving neither publisher drops the other's datasets, and a sync→refresh→sync test proving the incremental-change baseline is not destroyed |
| T-07-09 | Spoofing | workspace resolution in the relocated logs acquisition | high | mitigate | Move workspace resolution unchanged — only validated server-owned connection mappings are queried; add a test that a caller-supplied workspace id is not honoured |
| T-07-10 | Information Disclosure | relocated ARG/Logs acquisition | medium | mitigate | Preserve the existing connection-context and requested-scope stamping on every row so scope enforcement downstream keeps its inputs; assert scope attributes survive the move |
| T-07-11 | Repudiation | source status and evidence after relocation | medium | mitigate | Characterization suite asserts evidence engine/table/observed_at/query_version remain populated on relocated rows |
| T-07-12 | Denial of Service | two writers against one generation root | medium | mitigate | Inventory publication reuses the existing run lock or an equivalent, so concurrent Hermes sync and inventory refresh cannot interleave a partial generation |

No package-manager installs occur in this plan, so no package-legitimacy gate applies.
</threat_model>
