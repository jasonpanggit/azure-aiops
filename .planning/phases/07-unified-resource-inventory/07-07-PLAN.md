# Plan: Populate the Fabric Inventory Snapshot

## Goal

Make the deployed Inventory page show authorized rows by completing the Fabric refresh path and verifying the API can read the resulting OneLake tables.

## Tasks

### 1. Run the configured Fabric inventory refresh

- Use the deployed subscription-connection registry and configured ARG/LAW credentials.
- Execute the Fabric Inventory Refresh pipeline or its authenticated API trigger.
- Confirm each active subscription connection reports completed or an explicit actionable failure.

### 2. Resolve source authentication failures

- Replace the container-local `az login` dependency for the scheduled refresh path with the deployment's managed identity/service-principal credential, or configure the refresh worker with that credential.
- Confirm ARG queries are scoped per subscription connection and LAW access is available.
- Record the existing LAW `ConfigurationData` absence as degraded software inventory when it remains unavailable.

### 3. Verify publication and API reads

- Confirm non-empty `inventory_os_observations`, `inventory_software_observations`, and resource tables exist in the configured Fabric lakehouse.
- Confirm the API managed identity can read those tables.
- Reload `/inventory` and verify OS/software rows, evidence, freshness, and source-status messaging.

### 4. Improve the no-snapshot user path

- Add a visible refresh status/action or deployment/onboarding guidance when no active inventory snapshot exists.
- Keep empty and degraded states distinct from a successful populated snapshot.

## Verification

- Authenticated browser walkthrough of `/inventory`.
- Authenticated API checks for `/api/v1/inventory/os`, `/software`, `/paas`, and `/resources`.
- Re-run Phase 7 UAT after the snapshot is populated.
