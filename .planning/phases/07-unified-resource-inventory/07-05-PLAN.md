<objective>
Add the PaaS family and replace all-or-nothing inventory availability with per-family availability.

Purpose: INV-08 and INV-09. Per D-15, PaaS is acquired by projecting from the generic `Resources` query the inventory domain now issues itself — there is no acquisition gap, only a projection gap, since `_entity_type_for_resource()` already buckets every non-VM/Arc resource into a generic entity type. Per D-16, targeted per-family query specs are deferred until PaaS lifecycle signals are actually needed. Per D-13/D-14, the all-or-nothing snapshot check that produces today's 503 is replaced by per-family availability.

Output: a PaaS family end to end from acquisition to route, and per-family availability across every family.
</objective>
