This decision is recorded here rather than asked interactively because CONTEXT.md's Mode is "Autonomous recommended defaults" and the correct default is unambiguous.

## Information Architecture

Phase 10's web surface is **not a new route**. It is a new tab inside the existing `/connections` page (`web/src/app/connections/page.tsx`), matching the established `role="tablist"` pattern already used on `/inventory` (`web/src/app/inventory/page.tsx:776`).

| Element | Spec |
|---|---|
| Tab list | `<div role="tablist" aria-label="Data & integrations views" className="tab-list">` placed directly under the page's single `PageHeader`, above both tab panels. |
| Tab 1 (default/current) | id `subscriptions-tab`, controls `subscriptions-panel`, label **"Subscriptions"** — wraps the page's existing onboarding/health table content verbatim (no visual change). |
| Tab 2 (new) | id `fabric-medallion-tab`, controls `fabric-medallion-panel`, label **"Fabric medallion"** — hosts everything this phase adds. |
| Tab persistence | Selected tab is local component state (`useState<"subscriptions" \| "fabric-medallion">`), not URL-driven — consistent with `/inventory`'s `InventoryTab` pattern (no query-string dependency found there either). |
| `PageHeader` | Stays singular at the top of the page (not per-tab). `description` copy is extended, not replaced, so existing subscription-onboarding language is preserved: *"Operational coverage, freshness, credential health, and business context for every onboarded Azure subscription, plus Fabric medallion (Bronze/Silver/Gold) publication health."* |

### Fabric medallion panel layout (top → bottom)

1. `EvidenceBar` scoped to the Fabric health envelope (its own `knowledge_version`/`warnings`, independent of the Subscriptions tab's evidence).
2. `metric-grid` (4 `MetricCard`s): **Bronze tables**, **Silver tables**, **Gold tables**, **Governed relationships** — each showing `{healthy}/{total}` with a `detail` line naming the gap category (matches the existing `Connections`/`stale` MetricCard idiom).
3. A `callout` row (0–2 items, conditionally rendered — never empty space) for **capacity status** (paused/throttled) and **publication rollout stage**, styled exactly like the existing `stale-connections-callout` (`callout callout-warning`) and reusing `callout-critical`/`callout-success` tones.
4. Three layer sections, each a `card` with a `card-header` (layer name + one-line description + `MetricCard`-style inline counts) and a `card-body` containing a dataset table:
   - **Bronze layer** (`section` id `bronze-layer`)
   - **Silver layer** (`section` id `silver-layer`)
   - **Gold layer** (`section` id `gold-layer`)
   Each dataset table reuses `TableColumnFilters` (filter by status, freshness band, lineage source) + `operations-table` + `TablePagination`, identical composition to the Subscriptions table already on this page.
5. **Publication manifest & lifecycle** panel (`card`) — one row per dataset disposition: `active`, `dormant` (intentionally empty, physically present), `retired` (versioned compatibility evidence), `deployment-blocked`.
6. **Governance gaps** panel (`card`) — reuses the `.compliance-list`/`.compliance-row` grid pattern from `compliance/page.tsx` (uncommitted, but already an established sibling pattern) for missing-ownership and missing-tag rows, plus a referential-integrity blocker sub-list.
7. **Ingestion history / failed runs** panel (`card`) — reuses the same `.compliance-list`/`.compliance-row` idiom; each row is one run with a retry affordance styled like the existing `button button-quiet` "Sync now" action.
8. **Semantic model & Data Agent readiness** panel (`metric-grid`, `MetricCard`s with `size="text"` for qualitative values — same pattern as `metric-value-text` elsewhere) — one card each for: semantic model deployment state, Data Agent grounding evaluation status, and a `coverage` map card (reusing the `Record<key, "available" | "unknown">` idiom introduced in the uncommitted `DefenderOverview` type) for optional Fabric preview surfaces that cannot be auto-deployed.

The four Bronze/Silver/Gold/Governed-relationships `MetricCard`s are the primary visual anchor; the capacity and rollout callouts become the secondary anchor only when attention is required.

No new page-level route, no new left-nav entry (`AppShell.tsx` `WORKBENCH_NAV` is unchanged — `"/connections"` already exists there as **"Data & integrations"**).

## Status & State Vocabulary

Extend `statusTone()` in `web/src/components/ui/StatusBadge.tsx` with the dataset/manifest vocabulary from CONTEXT.md's decisions — do not invent a parallel badge component.

| Status keyword | `StatusBadge` tone | Badge label copy | Used for |
|---|---|---|---|
| `healthy` | `success` | "Healthy" | dataset meets freshness/SLO and has rows |
| `healthy-empty` | `success` | **"Healthy · Empty"** (never plain "Empty") | zero rows *with* healthy source status — must never look like a failure; render the row count as `0 rows (expected)` in the secondary line, not as a bare `0` |
| `stale` | `warning` | "Stale" | beyond configured freshness objective, last run otherwise succeeded |
| `degraded` | `warning` | "Degraded" | partial provider/source failure, some data still usable |
| `failed` | `critical` | "Failed" | last ingestion/publication run failed |
| `unavailable` | `critical` | **"Unavailable"** (never reuse "Failed" copy) | the source/provider itself could not be reached — distinct root cause from `failed`, must read differently to an operator scanning the table |
| `retired` | `neutral`/`unknown` | "Retired" | versioned compatibility disposition — dormant by design, excluded from health denominators |
| `deployment-blocked` | `warning` | "Deployment blocked" | semantic model / Data Agent surface validated but not auto-deployable |
| `dormant` | `neutral`/`unknown` | "Dormant" | manifest entry physically present but intentionally inactive |

**Never let "0 rows" alone imply success or failure** (CONTEXT.md decision) — every dataset row always pairs a status badge with an explicit row-count/last-run secondary line, so `healthy-empty` and `unavailable` are visually and textually distinguishable even though both may show `0` in a raw count column.

**Failed vs. unavailable copy distinction (concrete):**
- Failed run row: *"Ingestion failed — {n} of {n} attempts exhausted · last error: {message}"* with a **"Retry ingestion"** quiet button.
- Unavailable row: *"Source unavailable — Fabric capacity or workspace could not be reached"* with **no retry button** (retrying won't help until capacity/connectivity is restored) — instead a link-styled note pointing at the capacity-status callout in step 3 of the layout.

## Spacing Scale

Declared values (must be multiples of 4) — this matches the token set already defined in `:root` (`--radius-sm/md/lg`, `--topbar-height`, `--sidebar-width`) even though it isn't spelled out as spacing variables today:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | badge/icon gaps, `status-dot` spacing |
| sm | 8px | compact control spacing, form label gaps |
| md | 16px | default element spacing, `metric-grid`/`compliance-layout` gaps |
| lg | 24px | section padding between stacked cards |
| xl | 32px | `page-container` outer horizontal padding |
| 2xl | 48px | not used by this phase |
| 3xl | 64px | not used by this phase |

**Exceptions:** all *reused* primitives keep their existing, slightly off-grid padding verbatim — do not "fix" them as part of this phase: `.card-header` (`17px 19px`), `.card-body`/`.compliance-detail` (`19px`), `.metric-card` (`17px 18px`). These are pre-existing shared classes; changing them would be an unrelated, unrequested design-system refactor. Every *new* layout introduced by this phase (the tab list wrapper, the new panel stack, callout spacing) must use only the 4px-multiple tokens above.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Refresh Fabric health"** — re-fetches the layer/manifest/governance/readiness snapshot; button styled `button button-primary`, placed in `PageHeader`'s `actions` slot only while the Fabric medallion tab is active (mirrors the existing "Onboard subscription" action, which stays visible only for the Subscriptions tab) |
| Empty state heading | "No Fabric medallion datasets registered" |
| Empty state body | "Complete an initial subscription sync to publish Bronze, Silver, and Gold datasets. Layer health appears here once the first sync completes." |
| Error state | "Fabric medallion health is unavailable" — body: "{error.message} Check Fabric capacity and workspace connectivity, then retry." (verbatim pattern match to the Subscriptions tab's existing `StatePanel` error copy) |
| Partial/degraded state | Per-layer, not page-wide: if only Gold fails to load while Bronze/Silver succeed, render the Gold `card-body` as its own `StatePanel tone="error"` inside that one card — the other two layer cards and the summary metrics stay populated. Page never blanks for one layer's failure (CONTEXT.md: "a missing or degraded family degrades that family only"). |
| Failed run row (retryable) | "Ingestion failed — {n} of {n} attempts exhausted · last error: {message}" + button **"Retry ingestion"** |
| Unavailable row (not retryable) | "Source unavailable — Fabric capacity or workspace could not be reached" — no retry button; links to the capacity-status callout |
| Governance gap row | "{count} resources missing {ownership \| tags}" with a `warning`-toned `StatusBadge` — plural-safe: "1 resource missing ownership" / "84 resources missing ownership" |
| Deployment-blocked semantic surface | "Semantic model definition validated, not yet deployed — {reason}" (never silently reports success per CONTEXT.md) |
| Capacity paused callout | "Fabric capacity {name} is paused. Ingestion and publication are on hold until it resumes." (`callout callout-warning`) |
| Destructive confirmation (if planner adds retire action) | "Retire dataset "{name}"? This marks it dormant in the publication manifest; existing consumers see it as retired. Underlying Fabric tables are not deleted." — same `window.confirm()` pattern as the existing "Delete subscription connection" flow |

## Responsive & Accessibility

| Concern | Contract |
|---|---|
| Breakpoints | Reuse existing app breakpoints only — no new ones: `1100px` (nav/topbar), `900px`/`820px` (multi-column layouts collapse to single column), `640px`/`560px` (dense controls stack). The `metric-grid` inside the Fabric medallion panel collapses via the existing `@media (max-width: 1100px) { .metric-grid { ... } }` rule already governing every other metric grid — no page-specific override needed. |
| Tab list on narrow viewports | Reuses the existing `.tab-list`/`[role="tab"]` responsive rules already defined at `@media (max-width: 820px)` and `@media (max-width: 560px)` in `globals.css` (lines 5489/5510) — no new CSS. |
| Focus visibility | All new interactive elements (tabs, "Refresh Fabric health", "Retry ingestion") inherit the global `button:focus-visible, a:focus-visible { outline: 2px solid var(--color-brand); outline-offset: 2px; }` rule — no custom focus styling. |
| Live regions | `StatePanel` already sets `role={tone === "error" ? "alert" : "status"}` — reused as-is for every loading/error panel in this phase; no new `aria-live` wiring required. |
| Labels | `role="tablist"` gets `aria-label="Data & integrations views"`; each dataset table's `TableColumnFilters` gets `aria-label="Table column filters"` (existing default); the capacity-status callout region uses a `<strong>` lead-in exactly like `stale-connections-callout`, not a bare `<div>`, so it reads sensibly to a screen reader. |
| Reduced motion | The `.metric-critical::before` pulse animation (used when a layer summary card is in `critical` tone) already respects the existing global `@media (prefers-reduced-motion: reduce)` block — no new animation is introduced by this phase, so no new opt-out is needed. |
| Color-only status | Never rely on badge color alone — every `StatusBadge` in this phase pairs with explicit text label copy (per Status & State Vocabulary table) and a secondary descriptive line, matching the existing app-wide rule (`status-dot` + text, never a bare colored dot). |
