  <behavior>
    RED:
    - `query_gold_grounding()` against a mocked `httpx` transport returning a valid MCP result parses and returns the result dict.
    - `query_gold_grounding()` retries up to `MAX_RETRIES=2` on `httpx.HTTPError`/`json.JSONDecodeError`, with exponential backoff (`0.5 * 2**(attempt-1)`), then raises `GoldGroundingUnavailable` after exhausting retries.
    - An MCP result with `result.isError == True` raises `GoldGroundingUnavailable` immediately (no retry — this is the documented opaque "run failed before producing a result" case), carrying the result's `content[0].text` as the exception message.
    - `GoldGroundedCitation` requires `gold_table`, `row_key` (both non-empty), `as_of` (datetime), `confidence` (0.0-1.0); missing/invalid any of these raises a Pydantic `ValidationError`.
    - `GoldGroundedFinding` requires `citations` to have `min_length=1` — an empty citation list raises `ValidationError`, per Critical Failure Mode #1 ("answers cite... facts not present in the... evidence").
    - `GoldGroundedFinding._require_scoped_ids` raises `ValidationError` if any `resource_ids` entry does not start with `/subscriptions/`.
    - On a third consecutive `pydantic.ValidationError` while parsing line-delimited Data Agent output, the parser returns `GoldGroundedFinding(..., degraded=True, degraded_reason="unparseable Gold evidence")` rather than raising — evidence is never silently promoted or silently dropped (Critical Failure Mode #4).
    - `GoldGroundingMetrics.record_query()` increments `queries`/`degraded`/`latency`/`citation_count` counters with only low-cardinality attributes (`degraded: str(bool)`, truncated `reason`), never a payload/citation/question value.
    RED tasks below implement these as failing tests first, then the minimal code to pass, per the RED→GREEN→REFACTOR cycle.
  </behavior>
