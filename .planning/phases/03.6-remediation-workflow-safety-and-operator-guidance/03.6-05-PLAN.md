<objective>
Implement the Phase 03.6 UI-SPEC's "Recovery Controls Contract" (Cancel /
Retry / Supersede, independently gated) and "Always-visible execution facts",
"Reconciliation Contract", and "Lineage Contract" sections inside
`ExecutionAudit`. This replaces today's single `execution.retryable`-gated
Retry button with the full set the backend (Phases 03.2-03.4) already
exposes via `remediationApi.cancel`/`retry`/`supersede` (typed, currently
unused by `page.tsx`), per CONTEXT.md's "Recovery Controls and Polling"
decision group: "Retry, supersede, cancel, or wait controls are rendered
only from server-authoritative eligibility fields" and "Selected provider
counts, remaining attempts, verification deadline, reconciliation result,
and audit lineage remain visible."

Purpose: gives the operator every bounded recovery action the backend
already supports, and every fact needed to understand *why* a given action
is or isn't available -- without duplicating any backend eligibility logic
client-side.
Output: `RecoveryControls`/`ReconciliationSummary` components, wired into
`ExecutionAudit` alongside the always-visible facts and lineage.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-036-10 | Repudiation | Supersede reason field | medium | mitigate | `Confirm supersede` stays disabled until a non-empty reason is entered client-side (defense in depth only -- the server's own `supersede_reason_required` refusal, already shipped in Phase 03.3, remains the actual enforcement boundary). |
| T-036-11 | Elevation of Privilege | Recovery-control visibility | low | accept | Cancel/Retry/Supersede are lifecycle-contextual, not permission gates (per the UI-SPEC's explicit distinction from the Approve/Operate authorization gates) -- their visibility reflects execution *state* eligibility only; the actual RBAC/operate-scope check happens server-side on every write call exactly as it does today, unchanged by this plan. |
