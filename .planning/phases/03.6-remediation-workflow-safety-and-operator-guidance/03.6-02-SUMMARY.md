# Phase 03.6 Plan 02: Blocker Contract, Degradation Contract, Honest Step Projection, Real Citation Freshness Summary

> **Note:** This SUMMARY was generated retroactively (see 03.6-REVIEW.md WR-03) from
> `03.6-02-PLAN.md`'s locked `<behavior>`/`<action>` sections and the actual diff in
> `src/api/routers/remediation.py` / `src/semantic/live_operations.py`, since the
> original execution session did not produce it.

`plan_workflow` (`src/api/routers/remediation.py`) now assembles `workflow.blockers[]`
and `workflow.degradation[]` arrays and computes the `verify` step's status honestly
from `execution.status`/`evidence_reconciliation.status`/`remaining_attempts` instead
of collapsing every non-running execution to `"complete"`. `src/semantic/
live_operations.py`'s two hardcoded `"freshness": "current"` literals were replaced
with real threshold-based `classify_freshness(...)` computations.

## What Was Built

- **`src/api/routers/remediation.py`**:
  - `BLOCKER_STEP_BY_CODE: dict[str, str]` — a module-level constant mapping every
    code in the UI-SPEC's locked "Blocker Vocabulary" table (excluding
    `already_succeeded`) to its `Step` column value, with the four dual-sourced codes
    pinned to their run-time-arrival step per the UI-SPEC's note.
  - `_collect_blockers(*, preview_error, plan_ineligibility_reason, action_executable,
    latest_execution)` — assembles `{"code", "step"}` rows from `preview_error`
    (forced to `"review"`), `plan.ineligibility_reason`, `action.executable is False`
    (forced to `"approve"`), and `latest_execution.ineligibility_reason`/
    `failure_class == "verification_timed_out"`, excluding `already_succeeded`,
    deduplicated by exact `(code, step)` pair.
  - `_collect_degradation(context, plan)` — reads
    `plan.business_decision.source_family_status` for non-`"available"` entries, and
    (wrapped in `try/except`) `context.provider_runtime.health(refresh=False)`'s
    vulnerability-provider state, producing `{"source", "availability", "reason",
    "freshness"}` rows.
  - `plan_workflow`'s `verify` step status is now computed via `verify_blocked`/
    `verify_complete` booleans derived from `execution.status`/
    `evidence_reconciliation.status`/`remaining_attempts`, replacing the prior
    `"complete" if terminal else "current"/"pending"` collapse. `blockers`/
    `degradation` are added to the response envelope.
- **`src/semantic/live_operations.py`**: imports `classify_freshness` from
  `api.evidence`; `_configuration_plan`'s evidence-citation freshness field is now
  `classify_freshness(_text(row.get("last_assessed_at")))` (was the literal
  `"current"`); `_plan`'s evidence-citation freshness field is now
  `classify_freshness(self.freshness)` (was the literal `"current"`). `observed_at`
  fields are unchanged — only `freshness` fields were touched, per the plan's scope.
- **`tests/test_api_remediation_router.py`**: new test cases covering the verify-step
  honest-projection rule (failed/cancelled/reconciled_incomplete → blocked; clean
  succeeded → complete) and blockers/degradation assembly (preview_error,
  ineligibility_reason, action_not_executable, execution-level ineligibility_reason
  exclusion of `already_succeeded`, degraded source_family_status, and
  provider_runtime-absent non-raising behavior).

## Scope Decision (recorded per the plan's explicit instruction)

CONTEXT.md's "Surface patch-evidence canonical-target misses as structured coverage
counts" decision refers to a canonical-target-match step that exists in the
Fabric-dashboard `PatchIntelligence.from_semantic_engine` correlation path — a
different subsystem, never reached by `/remediation`. The *live* remediation planner
this plan actually touches builds every evidence citation from rows that already
passed a canonical-target join upstream in the live ARG/Resource-Graph query itself,
so there is no "evidence row dropped because it didn't match inventory" step in this
code path to count. `dropped_count`/`unmatched_count` are optional fields in the
locked Degradation Contract ("where known") and are correctly omitted here because
there is no real count to report — not because this work was skipped or deferred.
