# Phase 03.6 Plan 03: Patch Selection Safety Contract, Bounded Polling Contract, Type Contracts Summary

> **Note:** This SUMMARY was generated retroactively (see 03.6-REVIEW.md WR-03) from
> `03.6-03-PLAN.md`'s locked `<behavior>`/`<action>` sections and the actual diff in
> `web/src/lib/services.ts` / `web/src/app/remediation/page.tsx` /
> `web/src/app/remediation/polling.ts`, since the original execution session did not
> produce it.

`selectedPatchIds` is now `string[] | null` (`null` = all eligible patches), closing
CR-07's silent-widen-to-all bug on last-checkbox-deselect. Client polling for a
non-terminal execution is now bounded by a deterministic doubling backoff
(`usePollingBackoff`, extracted to `polling.ts`) capped at 40 requests or 600000ms
elapsed, whichever comes first. `services.ts` gained the `RemediationBlocker`/
`RemediationDegradation`/`RemediationEvidenceReconciliation` type contracts later
plans (03.6-04/05) consume.

## What Was Built

- **`web/src/lib/services.ts`**: `RemediationBlocker` (`code`, `message?`, `step`,
  `next_action?`, `severity?`), `RemediationDegradation` (`source`, `availability`,
  `reason`, `dropped_count?`, `unmatched_count?`, `freshness?`), and
  `RemediationEvidenceReconciliation` (`status`, `kbs_cleared`, `kbs_remaining`,
  `assessed_at`) interfaces added; `RemediationWorkflow` gained `blockers`/
  `degradation` fields; `RemediationExecution` gained `verification_deadline_at?`/
  `next_verification_at?`/`verification_attempts?`/`evidence_reconciliation?`.
- **`web/src/app/remediation/page.tsx`**: `selectedPatchIds` retyped from
  `useState<string[]>([])` to `useState<string[] | null>(null)`; a new
  `patchSelectionRefusal` string state for the transient refusal message; checkbox
  interaction now computes `current = selectedPatchIds === null ? allPatchIds :
  selectedPatchIds` and only ever calls `setSelectedPatchIds(null)` (all selected),
  `setSelectedPatchIds(next)` (non-empty explicit subset), or leaves state unchanged
  and sets `patchSelectionRefusal` (deselecting the last remaining patch); a mode line
  renders `"All eligible patches selected (N)."` or `"N of M patches explicitly
  selected."`; an evidence-refresh-reconciliation `useEffect` intersects a stale
  explicit selection against a newly-arrived `available_patches` list (removal-only,
  never widening), refusing (not silently falling back to "all") when the
  intersection is empty. Every wire-request call boundary applies
  `selectedPatchIds ?? []`.
- **`web/src/app/remediation/polling.ts`** (new): `usePollingBackoff({ active,
  resetKey, onPoll, now })` — `POLLING_BACKOFF_SEQUENCE_MS = [1500, 3000, 6000, 12000,
  24000, 30000]` (doubling, capped at 30000ms); `POLLING_MAX_REQUESTS = 40`;
  `POLLING_MAX_ELAPSED_MS = 600_000`; an injectable `now` clock (default `Date.now`)
  used only to measure elapsed time, never to schedule timers; returns `{ paused,
  requestCount, checkNow }`. The poll counter/elapsed-time clock reset whenever
  `resetKey` changes (plan or execution-id change gets a fresh full budget).
- **`web/src/app/remediation/page.test.tsx`**: new tests for the last-deselect
  refusal, the evidence-refresh-reconciliation narrowing/refusal, and (via
  `polling.ts`'s exported constants/hook) the two independent ceiling behaviors and
  the terminal-status stop-immediately behavior.
