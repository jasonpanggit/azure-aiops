Playwright E2E infrastructure (genuinely absent before this plan — no
`playwright.config.*`, no `@playwright/test` dependency, no `e2e/`/`*.spec.ts` files

three required Manual QA backstop checks were performed and recorded.

## What Was Built

- **`web/package.json`**: `@playwright/test` added to `devDependencies`; `"test:e2e":
  "playwright test"` script added.
- **`web/playwright.config.ts`** (new): `testDir: "./e2e"`; a `webServer` block
  running `npm run dev` with `NEXT_PUBLIC_ENTRA_CLIENT_ID` unset (forcing dev-token
  auth mode) and a fixed local `AIOPS_DEV_TOKEN`; `url: "http://127.0.0.1:3000"`;
  `reuseExistingServer: !process.env.CI`; single `chromium` project.
- **`web/e2e/remediation-workflow-safety.spec.ts`** (new): four passing specs —
  (1) smoke test: loads `/remediation` via dev-token auth and asserts the `Fix safely,
  one step at a time` heading renders; (2) blocker panel + degradation panel render
  with degradation preceding the Approve control in DOM order; (3) real-browser
  reproduction of CR-07 — unchecking the last remaining checked patch has no effect
  (both remain checked) and the refusal message renders; (4) an execution with only
  `cancellable: true` shows only the `Cancel queued execution` button. All mock their
  own `/api/v1/**` responses via `page.route()`, reusing the same fixture shapes as
  `page.test.tsx`'s `workflowFixture()`/`executionRecord()` helpers (copied, not
  imported across the Vitest/Playwright boundary).
- **`.planning/phases/03.6-remediation-workflow-safety-and-operator-guidance/
  03.6-MANUAL-QA.md`** (new): all three UI-SPEC-mandated backstop items (KB-list
  overflow, 375px responsive layout, screen-reader reading order) recorded PASS, dated
  2026-09-04, performed via Playwright 1.58.2/Chromium automated browser inspection
  (screenshots + `locator.ariaSnapshot()`), honestly noting the method was automated
  rather than a literal human tester. The 375px item records one honest, out-of-scope
  caveat: a pre-existing, unrelated Fluent UI "Development mode" banner does not wrap
  at narrow viewports (logged for visibility, not fixed, since it predates Phase 03.6
  and is outside the blocker/degradation/recovery-control surface this item covers).
