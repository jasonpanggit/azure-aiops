# Phase 03.6 Plan 05: Recovery Controls, Reconciliation Summary, Lineage Summary

> **Note:** This SUMMARY was generated retroactively (see 03.6-REVIEW.md WR-03) from
> `03.6-05-PLAN.md`'s locked `<behavior>`/`<action>` sections and the actual diff in
> `web/src/app/remediation/page.tsx`, since the original execution session did not
> produce it.

`RecoveryControls` now renders Cancel/Retry/Supersede independently from their own
server-authoritative eligibility booleans (replacing the prior single
`retryable`-gated button), with confirm/reason flows for Cancel and Supersede.
`ReconciliationSummary` and a Lineage block render always-visible execution facts
(remaining/submitted attempts, verification deadline, next check, evidence
reconciliation, supersede lineage) independent of which recovery controls are shown.

## What Was Built

- **`RecoveryControls({ execution, onCancel, onRetry, onSupersede, submitting,
  supersedeIneligibilityReason })`**: renders, strictly conditionally (hidden, never
  shown-disabled) — `Cancel queued execution` (when `cancellable`), with a
  `role="alertdialog"` confirm callout; the existing `Retry approved snapshot` button
  (when `retryable`); `Supersede this execution` (when `supersedable`), revealing a
  required `Reason` textarea and a `Confirm supersede` button disabled until non-empty.
  When `supersedeIneligibilityReason` is present, renders it via the shared
  `blockerCopy(supersedeIneligibilityReason, "verify").message` (Plan 03.6-04's
  function, reused not duplicated) as a `callout-warning`.
- **Parent (`RemediationContent`) handlers**: `cancelExecution`/`supersedeExecution`
  mirror `retryExecution`'s shape — call the API, refresh workflow, surface errors via
  the existing `actionError` callout; a caught supersede error whose `ApiError.
  details.reason` matches a vocabulary code sets `supersedeIneligibilityReason` and
  triggers a refresh (reusing the read-side race-handling callout path, not a second
  copy path).
- **Always-visible execution facts** (inside `ExecutionAudit`, above
  `RecoveryControls`): `Remaining attempts`, `Submitted attempts`, `Verification
  deadline` (or "Verification deadline passed"), `Next automatic check` — each renders
  independently of which recovery controls are visible.
- **`ReconciliationSummary({ reconciliation })`**: renders nothing when absent/empty
  `status`; else the locked per-status copy table with matching `StatusBadge` tone,
  plus a `kbs_cleared` secondary line and code-formatted KB id lists.
- **Lineage rendering**: `Supersedes execution {id}.` / `Superseded by execution {id}:
  {reason}.` as plain text with monospace ids, no link.
- **`.remediation-recovery`/`.remediation-supersede-form`** added to `globals.css`.
- **`web/src/app/remediation/page.test.tsx`**: new tests for each control-visibility
  combination, the Cancel/Supersede confirm flows against mocked
  `remediationApi.cancel`/`.supersede`, the race-refusal callout, the always-visible
  facts, `ReconciliationSummary`'s status variants, and lineage rendering. The
  reconciliation-pending `Check reconciliation` one-off-refresh button (Task 3) was
  also wired and tested, plus a full-suite regression pass across Plans 03.6-03/04/05.
