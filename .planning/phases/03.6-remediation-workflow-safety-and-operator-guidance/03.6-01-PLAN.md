<objective>
Close the Phase 03.6 UI-SPEC's "Failure Details Authoritative Contract" (backend
requirement): make `execution.failure_details` reliably non-empty on every
execution that reaches a terminal `"failed"` status, so the Verify step's
pre-submission/post-submission honesty sentences (built later in this phase,
Plan 03.6-04) never read from an empty field. Today three call sites in
`poll_verification`/`reconcile_ambiguous_submission` pass a human-readable
`message=` note but omit the identical text as `failure_details=`, per D-04
("Failed, cancelled, unknown, unreconciled, and exhausted executions block
Verify and recommend the actual available recovery action" -- CONTEXT.md
"Honest Lifecycle Projection") and the UI-SPEC's locked "Failure Details
Authoritative Contract".

Purpose: This is a pure parameter-plumbing fix (reuse the existing `message=`
text verbatim as `failure_details=`) plus the exhaustive regression test the
UI-SPEC requires as an explicit, equal-weight acceptance criterion. It has no
UI-visible effect on its own; Plan 03.6-04 depends on this field being
trustworthy.
Output: `execution_service.py`'s three under-populating call sites fixed, plus
one new exhaustive test file proving every terminal-failure call site (the
three fixed here, plus the one pre-submission path that was already correct)
populates `failure_details`.
</objective>
