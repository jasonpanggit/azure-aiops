<objective>
Implement the Phase 03.6 UI-SPEC's "Patch Selection Safety Contract" and
"Bounded Polling Contract" in `web/src/app/remediation/page.tsx`, and extend
`web/src/lib/services.ts`'s type contracts so later plans in this phase
(03.6-04, 03.6-05) can consume `workflow.blockers`/`workflow.degradation` and
the execution's verification/reconciliation fields without further type
changes. This closes CR-07 (the existing
`setSelectedPatchIds(next.length === all.length ? [] : next)` bug that
silently re-selects every patch when the operator deselects the last one) and
the unbounded `setTimeout(() => refresh, 1500)` polling loop (`page.tsx`
today), per CONTEXT.md's "Patch Selection Safety" and "Recovery Controls and
Polling" decision groups.

Purpose: makes patch approval fail-safe (an operator can never approve an
empty set, and can never be silently upgraded to "all patches" by a
deselect gesture) and makes client polling for a stuck execution bounded and
independently testable, both locked, standalone UI-SPEC contracts that do not
depend on this phase's backend or blocker/degradation-rendering work.
Output: a corrected patch-selection state model, a bounded polling mechanism,
and the extended `services.ts` type surface the rest of this phase's frontend
plans build on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator checkbox interaction -> `selected_patch_ids` wire payload | Client-local UI state only; the server (unchanged by this plan) remains the authority on which patches are actually eligible -- this plan only prevents the client from ever constructing an empty-set request. |
| browser -> `GET /plans/{id}/workflow` (polling) | Rate-bounded from the client side by this plan; the server itself is the actual rate-limiting authority for abuse (out of scope here, unchanged). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-036-06 | Tampering | Patch-selection state model | high | mitigate | The empty-selection refusal (Task 2) is the direct mitigation for CR-07 -- an operator can no longer widen an approved blast radius back to "all eligible patches" via a deselect gesture; the server-side snapshot-hash binding (unchanged, already existing) remains the final authority regardless. |
| T-036-07 | Denial of Service | Unbounded client polling against `GET /plans/{id}/workflow` | medium | mitigate | The bounded backoff + hard ceiling (Task 3) is the direct mitigation -- a stuck execution's browser tab can no longer issue an unbounded number of requests indefinitely; capped at 40 requests or 10 minutes per execution. |

</threat_model>
