# Phase 12 — UI Design Contract

> Visual and interaction contract for the Network page changes in Phase 12.
> Generated by gsd-ui-researcher from CONTEXT/REVIEW/RESEARCH plus direct code inspection.
> Consumed by gsd-ui-checker, gsd-planner, gsd-executor, gsd-ui-auditor.

**Governing principle for this phase:** *nothing on this page may imply completeness, cleanliness, or freshness
that the data does not support.* Every contract below exists to make an omission visible rather than silent.

## Status & State Vocabulary

Extend `statusTone()` in `web/src/components/ui/StatusBadge.tsx` with the Phase-12 vocabulary. Never invent a
parallel badge component.

| Keyword | Tone | Badge label copy | Meaning |
|---|---|---|---|
| `complete` | `success` | "Complete" | every item in the collection was loaded; totals and badges are exhaustive |
| `partial` | `warning` | "Partial — N of M" | a bounded result; **must always carry both numbers** |
| `unavailable` | `critical` | "Unavailable" | the request failed; state is unknown, **not** clean |
| `not-analyzed` | `warning` | "Ingested, not analyzed" | flow observations exist but no analyzer consumes them (D-22) |
| `private-link-candidate` | `info` | "Private link candidate" | a private-link resource projected as topology context |
| `public-access-enabled` | `critical` | "Public network access enabled" | `public_network_access == "Enabled"` on a private-link candidate |
| `stale` | `warning` | "Stale" | freshness band from server `classify_freshness` |
| `unknown` | `unknown` | "Unknown" | freshness or provenance genuinely undetermined |
| `peer-not-ingested` | `warning` | "Not ingested" | the peer VNet exists in Azure but is in no onboarded connection; nothing beyond it was ever collected (C-10) |
| `peer-out-of-scope` | `info` | "Outside current scope" | the peer VNet **was** ingested and is present in the unscoped snapshot, but the active scope selection excludes it (C-10) |
| `peer-resolution-unknown` | `unknown` | "Peer resolution unknown" | a legacy payload carried no `peer_resolution`; the UI must not guess which of the two above applies (C-10) |

`statusTone()` gains these keywords additively. `peer-not-ingested` → `warning` and `peer-out-of-scope` → `info` are
new mappings on new strings; **no existing keyword changes tone.**

### The three-way honesty rule (applies to every collection on this page)

Any list, count, badge, drawer section, or export in this phase resolves to exactly one of three states, and the
three must be **textually distinguishable**, not only tonally:

| State | Meaning | Never rendered as |
|---|---|---|
| **Complete + empty** | loaded successfully, genuinely zero items | a missing section, `null`, or a bare `0` |
| **Partial** | loaded successfully, bounded by a limit/cap | "complete", or the page-size number presented as a total |
| **Unavailable** | request failed or was not attempted | "empty", "clean", or "0" |

A component that cannot distinguish these three MUST NOT render a verdict.

### Retry affordances — accessible names must be unique

Phase 12 introduces **six** Retry buttons on one page. A screen-reader user tabbing the page would otherwise hear
"Retry, button" six times with no way to tell which surface each one repairs, and an automated a11y check would
flag duplicate accessible names. **Every Retry button therefore carries a distinct accessible name.** The *visible*
label stays the short word **Retry** in every case; the distinction is carried by `aria-label`, which overrides the

Retry rules:

- Pressing Retry re-invokes **only** that loader's `refetch()`. It never triggers a page reload and never refetches
  the other three loaders.
- While a retry is in flight the button is `disabled` with `aria-busy="true"`; its accessible name does **not**
  change (a name that mutates mid-announcement is worse than a static one).
- A retry that fails again re-renders the same `StatePanel` with the new `{error}`. The button is never removed.
- Save/preview failures deliberately have **no** Retry button: the primary button *is* the retry, and adding a
  second one would imply the failed submission is separately re-sendable.

### Freshness copy — deterministic per surface

`graph_freshness` is rendered on **three** surfaces with **three fixed strings**. There is no third variant, no
"just now", and no relative time when the value is absent, empty, unparseable, or at/before the Unix epoch.

| Surface | Form | Exact copy when freshness is unknown |
|---|---|---|
| `EvidenceBar` chain segment | short chip | **`Unknown`** — rendered as the segment value, so the segment reads `Graph Unknown` |
| `TopologyDetailDrawer` freshness footnote | long form | **`Snapshot age unknown — no observation timestamp was recorded.`** |
| `.topology-footnote` freshness item | long form | **`Snapshot age unknown — no observation timestamp was recorded.`** |

| Surface | Exact copy when freshness is known |
|---|---|
| `EvidenceBar` chain segment | `relativeTime(graph_freshness)`, e.g. `2 hours ago` — unchanged from today |
| Drawer / footnote long form | `Snapshot observed {relativeTime(graph_freshness)} ({formatDateTime(graph_freshness)}).` |

**`relativeTime()` is NOT changed and NOT bypassed for valid input; it IS bypassed for unknown input.** Stated
precisely, because the checker flagged this as ambiguous:

1. `web/src/lib/format.ts` is **not modified by this phase.** `relativeTime()` keeps its current signature and its
   current `if (!value) return "Freshness unknown"` behaviour. It is used unchanged by Connections, FinOps,
   Governance, Situations, Investigate, and the `EvidenceBar` `Updated` and `Live` segments — none of which this
   phase touches.
2. The reason for bypassing rather than editing it: `relativeTime()`'s existing unknown-string is
   **`"Freshness unknown"`**, which is neither of the two strings this contract requires, and it returns a
   *relative time* for an epoch-zero or otherwise nonsense-but-parseable stamp (`new Date(0)` → `"56 years ago"`).
   Editing it to satisfy this contract would silently rewrite six other pages' copy.
3. A new **local, non-exported** guard `freshnessChip(value)` in `EvidenceBar.tsx` decides between the two paths:

   ```ts
   // returns "Unknown" for absent, empty, unparseable, or at/before-epoch input;
   // otherwise defers to the shared relativeTime() unchanged.
   function freshnessChip(value?: string): string {
     if (!value) return "Unknown";
     const ms = new Date(value).getTime();
     if (Number.isNaN(ms) || ms <= 0) return "Unknown";
     return relativeTime(value);
   }
   ```

4. The equivalent long-form guard lives in `TopologyWorkspace.tsx` / `TopologyDetailDrawer.tsx` and returns the
   `Snapshot age unknown — …` sentence under exactly the same four conditions, so a value that yields `Unknown` in
   the chip can never yield a relative time in the footnote. The two guards must agree on the same predicate —
   asserted by A42.

Other copy:

| Surface | Copy |
|---|---|
| Selection cleared by filter | Selection cleared — the selected resource is hidden by the current filter. |
| Peer not ingested (drawer) | **This peer was never ingested.** Its subscription is not onboarded, so topology beyond this point is unknown. |
| Peer excluded by scope (drawer) | **This peer is outside the current scope.** It was ingested and is present in the estate, but the active scope selection excludes it. Widen the scope to see it. |
| Peer resolution unknown (drawer) | **Why this peer is missing is not recorded.** This response did not say whether the VNet was never ingested or excluded by the current scope. |

11. The page-size selector's initially selected option is `20`.

### C-5 — Explicit drawer states: clean vs. truncated vs. unavailable · TOPO-03

**Problem being fixed:** `OpenFindings` returns `null` when a node has no findings. Combined with orphaned
findings (C-3) and the 100-item cap (C-1), a resource with real open findings renders a drawer with the entire
"Open findings" section **absent**, which reads as "this resource is clean". For a security-facing view this is
the most dangerous default on the page.

**Contract — the section is ALWAYS rendered when a node is selected.** `return null` is forbidden.

| Drawer state | Precondition | Rendering |
|---|---|---|
| **Findings present** | ≥ 1 finding mapped to this node | `<h3>Open findings ({n})</h3>` + grouped list (C-4) |
| **Confirmed clean** | both loaders succeeded **and** both collections were fully loaded (`coverage.truncated === false` and the badge fetch was exhaustive) **and** zero findings map to this node | `<h3>Open findings (0)</h3>` + `.muted` line: *"No open findings for this resource. All {N} gaps and {M} rule findings in scope were checked."* |
| **Possibly incomplete** | either loader is bounded (`coverage.truncated` or badge budget hit) and zero findings map to this node | `<h3>Open findings</h3>` + `.callout.callout-warning` `role="status"`: *"Findings for this resource may be incomplete. {mapped} of {total} findings were loaded. This resource is not confirmed clean."* |
| **Unavailable** | either loader rejected | `<h3>Open findings</h3>` + `.callout.callout-critical` `role="alert"`: *"Findings are unavailable — {error}. This resource is not confirmed clean."* + a **Retry** button (visible label `Retry`, accessible name R-5 `Retry loading findings for {resource name}`) that calls the loader's `refetch()` |

### C-7 — Freshness and flow-log provenance, both data-derived · TOPO-05

**Problem being fixed:** the page header renders a fixed `<span>No flow logs assumed</span>`, and `/rule-findings`
hardcodes medium confidence with the comment "no flow logs are ingested" — while a flow-log ingestion pipeline
exists. Separately, `_load_network_service()` discards the freshness value it computes, so topology freshness
degrades to `unknown` whenever ontology rows carry no per-row stamp, and the operator cannot tell a fresh topology
from a week-old one.

**Contract — flow-log provenance chip (`PageHeader.metadata`, third item)**

Exactly one of three data-derived strings. The string is chosen from server-reported provenance, never from a
constant:

| Provenance | Copy |
|---|---|
| No flow-log evidence in the snapshot | Flow logs: not ingested — findings are configuration-derived |
| Flow-log edges present but not consumed by the analyzer (D-22) | Flow logs: ingested, not yet analyzed — findings remain configuration-derived |
| Flow observations analyzed | Flow logs: {n} observed flows analyzed |

The middle state is mandatory. Replacing the hardcoded "no flow logs" with a data-derived "flow logs observed"
while `analyze_rules` still receives no observations would replace one untruth with another (RESEARCH pitfall P-7).

**Contract — freshness**

| Element | Rule |
|---|---|
| `EvidenceBar` prop | receives `graphFreshness={topology.data?.graph_freshness}`; the prop already exists on `EvidenceBarProps` and needs no signature change |
| **Unconditional segment** | **`EvidenceBar` is modified (additively) so the `graph` segment is always emitted.** Today it is built as `graphFreshness ? { key: "graph", … } : null` and then removed by the `.filter(...)` on the segment array — so an absent freshness value renders **no `Graph` segment at all**. A missing segment is not a disclosure; the operator sees a shorter chain and no signal that freshness is unknown. After this phase the segment is always in the array and its *value* carries the state. |
| Chip copy (unknown) | the literal word **`Unknown`**, so the segment reads `Graph Unknown`. Not "unknown", not "—", not "Freshness unknown", not a relative time. |
| Chip copy (known) | `relativeTime(graph_freshness)` — unchanged behaviour |
| Unknown predicate | absent · empty string · unparseable (`Number.isNaN`) · at or before the Unix epoch (`ms <= 0`). All four take the `Unknown` path. |
| `relativeTime()` | **not modified and not replaced.** `web/src/lib/format.ts` is read-only for this phase. It is bypassed **only** on the unknown path, via the local non-exported `freshnessChip()` guard in `EvidenceBar.tsx` (code in the Copywriting Contract). On the known path it is called exactly as today. Rationale: `relativeTime()`'s own unknown-string is `"Freshness unknown"`, which is neither of this contract's two required strings, and it happily returns `"56 years ago"` for an epoch-zero stamp. Editing it would silently rewrite the same chip on Connections, FinOps, Governance, Situations, and Investigate. |
| Other `EvidenceBar` segments | `Source`, `Updated`, `Knowledge`, and `Live` are **unchanged**, including `Updated`'s existing `relativeTime(timestamp)` call and its `"Freshness unknown"` output. Making those unconditional too is **out of scope** for this phase. |
| Cross-page effect | every page rendering `EvidenceBar` without `graphFreshness` gains one `Graph Unknown` segment. This is intended: those pages were already omitting an unknown, and the omission was the bug. Declared here so the auditor does not read it as unrelated drift. |
| Long-form copy (unknown) | `.topology-footnote` and the drawer render the full sentence **`Snapshot age unknown — no observation timestamp was recorded.`** |
| Long-form copy (known) | `Snapshot observed {relativeTime(v)} ({formatDateTime(v)}).` |
| Guard agreement | the long-form guard uses the **identical four-condition predicate** as `freshnessChip()`. A value that produces `Unknown` in the chip must never produce a relative time in the footnote or drawer, and vice versa. |
| Band vocabulary | `fresh` / `aging` / `stale` / `unknown` from the server's `classify_freshness`; the UI never re-derives a band from a timestamp |
| Tone | `fresh` → `success`, `aging` → `warning`, `stale` → `warning`, `unknown` → `unknown`. No new tone. |
| Warnings | dropped-relationship diagnostics arrive as envelope `warnings[]` and surface through the existing `EvidenceBar` `warnings` prop — **no new warning surface** |
| Dropped-edge visibility | when `topology.counts.dropped_relationships` is present and non-zero, the footnote appends `{n} relationships dropped ({types})`; when present and zero, it appends nothing (a zero is not news) |
| Framing | the first render of a non-zero dropped-edge count is newly-surfaced pre-existing loss, not new breakage. Copy must not say "error" or "failed": *"{n} relationships dropped ({attached_to}, {resolves_for}) — endpoints were not present in this scope."* |

**Measurable acceptance**

1. With a snapshot carrying no flow-log evidence, the header chip reads exactly "Flow logs: not ingested — findings are configuration-derived".
2. With flow-log-tagged edges present but no analyzer wiring, the chip contains "not yet analyzed".
3. The literal string "No flow logs assumed" no longer exists anywhere in `web/src/`.
4. With `graph_freshness` absent, empty, unparseable, or `1970-01-01T00:00:00Z`, the `EvidenceBar` renders a segment labelled `Graph` whose value is exactly the string `Unknown` — in all four cases, and never a relative time.
5. Rendering `<EvidenceBar />` with **no** `graphFreshness` prop still produces a `Graph` segment (the segment is never filtered out).
6. With `graph_freshness` set to a recent stamp, the segment renders a relative time and the confidence badge tone matches the server band.
7. With `graph_freshness` absent, the topology footnote contains the exact sentence `Snapshot age unknown — no observation timestamp was recorded.` and does **not** contain the word "ago".
8. `git diff web/src/lib/format.ts` is empty: `relativeTime()` and `formatDateTime()` are byte-identical after this phase.
9. The string `"Freshness unknown"` never appears in the rendered `Graph` segment or in the topology footnote.
10. With `counts.dropped_relationships = {attached_to: 3}`, the footnote contains "3 relationships dropped" and the word "attached_to".
11. With `counts.dropped_relationships = {}`, the footnote contains no "dropped" text.

### C-10 — Peer resolution: not ingested vs. excluded by effective scope · TOPO-01, TOPO-05

**Problem being fixed:** the UI collapses two operationally opposite situations into one grey "Not onboarded" node.

Verified in the backend. `TopologyBuilder.build()` (`src/network/topology.py:223-229`) computes
`unresolved_peer_vnet_ids` from the **unscoped** snapshot — a peer is unresolved only when
`remote_vnet_observed` is false, i.e. `remote_id not in vnets` (`topology.py:278`). But
`NetworkIntelligenceService._scoped_topology()` (`src/network/service.py:313-333`) then does two things:

1. it drops every link whose endpoints are not both in `kept` — so a peering to a VNet that **was** ingested but is
   excluded by the active scope disappears entirely; and
2. it passes `unresolved_peer_vnet_ids=base.unresolved_peer_vnet_ids` **verbatim from the unscoped topology**.

So the list the UI renders is scope-blind. The frontend then labels every entry with a single fixed string —
`unresolved: "Peer VNet — not onboarded"` (`TopologyDetailDrawer.tsx:15`), the drawer callout *"This peer was never
ingested. Its subscription is not onboarded…"* (`:86-87`), the legend chip `Not onboarded`
(`TopologyWorkspace.tsx:203`), and the footnote `{counts.unresolved} peers not onboarded` (`:258`).

The result is a false statement. A VNet the operator deliberately filtered out of scope is reported to them as
never ingested — telling them their estate has a collection gap that does not exist, and hiding the fact that
narrowing scope silently reduced the topology. This is a scope-isolation honesty defect, which is locked decision 1
and the phase's first release gate.

**Contract — server selector field**

The server must state *why* a peer is missing rather than leaving the client to infer it.

| Element | Rule |
|---|---|
| **Selector field** | **`peer_resolution`** — a required string on each entry of the new `unresolved_peers[]` array in the `/network/topology` payload |
| Allowed values | exactly three: **`not_ingested`** · **`excluded_by_scope`** · **`observed`**. No other value may be emitted. |
| Container | `unresolved_peers: { vnet_id: string; peer_resolution: "not_ingested" \| "excluded_by_scope" \| "observed"; subscription_id?: string \| null }[]` |
| Backward compatibility | `unresolved_peer_vnet_ids: string[]` is **retained unchanged** and keeps its current membership, per locked decision 6 (additive fields, no silent contract flip). Agents, MCP tools, and exports that read it keep working. `unresolved_peers` is the additive superset. |
| Server derivation (`_scoped_topology`) | for each peer id referenced by a peering: `not_ingested` when the id is absent from the **unscoped** `topology.snapshot` VNets; `excluded_by_scope` when it **is** present in the unscoped snapshot but `scope.matches()` is false; `observed` when it survives the scope filter. When `scope.is_empty`, `excluded_by_scope` can never be emitted. |
| Server must not guess | if the unscoped snapshot is unavailable to the scoped call, the field is emitted as `not_ingested` **only** when that is provable; otherwise the peer is omitted from `unresolved_peers` entirely and the client falls back to the unknown state below. **A guess is never encoded as a resolution.** |
| Client type | `TopologyNodeData` gains `peerResolution?: "not_ingested" \| "excluded_by_scope" \| "observed" \| "unknown"` |
| Client fallback | a payload with `unresolved_peer_vnet_ids` but **no** `unresolved_peers` yields `peerResolution: "unknown"` for every unresolved node. The client **must not** default to `not_ingested` — defaulting is exactly the false statement this contract exists to remove. |
| Node kind | unchanged: `kind="unresolved"`, existing grey `#778290` / `#c9cfd7` dotted treatment. **No new node kind, shape, or colour.** |

**Contract — copy**

| Surface | `not_ingested` | `excluded_by_scope` | `unknown` |
|---|---|---|---|
| Drawer kind line (`KIND_LABELS.unresolved`) | `Peer VNet — not ingested` | `Peer VNet — outside current scope` | `Peer VNet — resolution not recorded` |
| Drawer callout (replaces the fixed `:86-87` copy) | **This peer was never ingested.** Its subscription is not onboarded, so topology beyond this point is unknown. | **This peer is outside the current scope.** It was ingested and is present in the estate, but the active scope selection excludes it. Widen the scope to see it. | **Why this peer is missing is not recorded.** This response did not say whether the VNet was never ingested or excluded by the current scope. |
| Callout class / role | `.callout.callout-warning` `role="status"` | `.callout.callout-info` `role="status"` | `.callout.callout-warning` `role="status"` |
| `StatusBadge` in the signals row | `Not ingested` (tone `warning`) | `Outside current scope` (tone `info`) | `Peer resolution unknown` (tone `unknown`) |
| Peering-edge label (`TopologyDetailDrawer.tsx:277`) | `Remote VNet not ingested` | `Remote VNet outside current scope` | `Remote VNet resolution not recorded` |
| Dependent-list badge (`:228`) | `Not ingested` | `Outside scope` | `Unknown` |
| Legend chip (`TopologyWorkspace.tsx:203`) | single entry, relabelled from `Not onboarded` to **`Peer VNet not shown`** — one swatch, because both states share one canvas treatment | | |
| Footnote (`TopologyWorkspace.tsx:258`) | replaces `{n} peers not onboarded` with up to three items, each rendered **only when non-zero**: `{a} peers not ingested` · `{b} peers outside current scope` · `{c} peers with unrecorded resolution` | | |
| Footnote, all zero | the whole group is omitted (a zero is not news, consistent with C-7's dropped-edge rule) | | |

**Declared visual limitation.** `not_ingested` and `excluded_by_scope` render **identically on canvas** — same grey,
same dotted border. This is deliberate: adding a colour would breach the no-new-colour rule, and adding a shape
would fork the node vocabulary. The distinction is carried **entirely in DOM text** (drawer kind line, drawer
callout, drawer badge, edge label, dependent-list badge, and the split footnote counts), which is the accessible
channel anyway. This is recorded as an accepted limitation in the same spirit as the private-link border contrast
note in the Accessibility section — the canvas is a locator, the DOM is the record. **The legend must therefore not
claim a distinction it does not draw**, which is why it collapses to one honest entry.

**Measurable acceptance**

1. Given an unscoped snapshot containing VNet-A (in scope), VNet-B (ingested, excluded by the active scope), and a peering from VNet-A to VNet-C (never ingested), the scoped `/network/topology` response emits `unresolved_peers` containing exactly `{vnet_id: B, peer_resolution: "excluded_by_scope"}` and `{vnet_id: C, peer_resolution: "not_ingested"}`.
2. `peer_resolution` only ever holds one of the three declared values; a fixture asserting the full enum fails if a fourth string is emitted.
3. With `scope.is_empty`, no entry carries `excluded_by_scope`.
4. `unresolved_peer_vnet_ids` is still present in the same response and still contains `C`, so an existing agent/MCP/export consumer reading only that key is unaffected.
5. Selecting VNet-C opens a drawer whose kind line reads `Peer VNet — not ingested` and whose callout contains "never ingested".
6. Selecting VNet-B opens a drawer whose kind line reads `Peer VNet — outside current scope`, whose callout contains "Widen the scope", and which does **not** contain the string "never ingested".
7. A payload carrying `unresolved_peer_vnet_ids` but no `unresolved_peers` renders every unresolved node with the kind line `Peer VNet — resolution not recorded`; the string "never ingested" appears nowhere in that render.
8. With one peer of each kind, the footnote contains both `1 peers not ingested` and `1 peers outside current scope` as separate items; with zero of a kind, that item is absent.
9. The literal strings `"not onboarded"` and `"Not onboarded"` no longer appear in `web/src/components/network/`.
10. Both node kinds still render as `kind="unresolved"`; no new `TopologyNodeKind` member is added.
11. Widening the scope to include VNet-B moves it out of `unresolved_peers` (or to `peer_resolution: "observed"`) and its node renders with its real kind, not `unresolved`.

## Accessibility Constraints

Baseline: WCAG 2.2 AA. Existing global focus treatment (`2px solid var(--color-brand)`, `outline-offset: 2px`)
applies to every new control and must not be overridden.

### Required

| Area | Requirement |
|---|---|
| Keyboard | Every new control — detail segmented control, drill-down buttons, Retry, assertion textarea, pagination, confirm-delete — is reachable and operable by keyboard in DOM order. No positive `tabIndex`. |
| Canvas | `.topology-canvas` keeps `role="application"` + `aria-label`. Cytoscape content is **not** screen-reader accessible, so **every signal expressed as a canvas badge must also exist as DOM text**: the footnote reports `{n} nodes with open findings` and the split peer-resolution counts, and the drawer reports each node's findings and peer resolution in full. A badge is never the only representation of a finding, and a node's grey dotted treatment is never the only representation of why it is missing. |
| Live regions | Coverage/truncation callouts and the selection-cleared announcement use `role="status"` (polite). Error callouts and validation failures use `role="alert"` (assertive). Exactly one assertive region may be active at a time. |
| Busy state | `aria-busy="true"` on the topology `<section>` during refetch and on the drawer findings section while loading. Not on `<body>`. |
| Focus management | Drawer focus moves to the close button on **selection change only** (C-5). Refetch, drill-down completion, and policy saves must not move focus. Closing the drawer returns focus to the canvas container. |
| Toggle semantics | Checkbox toggles keep `<input type="checkbox">` with a visible `<span>` label. The segmented control uses `<button aria-pressed>` inside `role="group"` with `aria-label="Topology detail level"`. Do not hand-roll a `role="radiogroup"` with manual arrow-key handling. |
| Form validation | Assertion textarea gets `aria-invalid="true"` and `aria-describedby="{errorId}"` when the server rejects it; the error element is rendered **before** the field in DOM order so it is announced on focus. |
| Confirm-delete | The two-step delete updates the button's accessible name from "Delete" to "Confirm delete" and announces the consequence via a polite live region. A destructive action must never be one keystroke from a focused button without an accessible-name change. |
| Colour independence | Every severity, freshness, coverage, provenance, and **peer-resolution** signal has a text equivalent in the same element. Severity is never conveyed by badge colour alone. The two peer-resolution states (C-10) share one canvas treatment by design and are distinguished **only** by DOM text — which makes them fully accessible, and is why the legend does not claim a visual distinction. |
| Accessible names | No two simultaneously-rendered controls may share an accessible name. This binds hardest on the six Retry buttons (R-1…R-6 in the Copywriting Contract): each carries a distinct `aria-label` that **begins with the visible word "Retry"**, satisfying WCAG 2.2 SC 2.5.3 Label in Name for voice control while remaining distinguishable in a screen-reader control list. |
| Contrast | New text ≥ 4.5:1; new non-text indicators (segmented-control active state, dashed private-link border) ≥ 3:1 against their adjacent surface. The private-link dashed border `#8a97a6` on `#eef2f7` measures ≈ 2.4:1, which is why the private-link signal is **also** carried by the drawer badge and the legend entry — the border alone is not a compliant indicator and must not be treated as one. |
| Motion | The `fit()` animation (200 ms) and any new transition must be disabled under `@media (prefers-reduced-motion: reduce)`. Detail-level switching must not animate a full re-layout. |
| Zoom | At 200% browser zoom, no content is lost or requires two-dimensional scrolling in the drawer or the toolbar. |
| Headings | Drawer sections stay `<h3>` under the drawer `<h2>`. New sections must not skip a level. |

### Explicitly forbidden

- Any modal dialog (the page has no modal pattern).
- Any tooltip that carries information not available elsewhere.
- `aria-hidden` on any element carrying a finding, count, or provenance value.
- `title` as the sole carrier of the badge count (it already is on canvas; the DOM mirror in the footnote and drawer is what makes it compliant).

## Performance and Rendering Budgets

These are **user-facing** budgets — they define when the UI must disclose or degrade, not internal optimisation
targets. Values are taken from the measured numbers in `12-RESEARCH.md` §Scale Budgets.

| Budget | Threshold | Behaviour when exceeded |
|---|---|---|
| Summary payload (small fixture) | ≤ 200 nodes **and** ≤ 250 KB | Gate G-1; requires stripping embedded `details`, not just dropping rule nodes |
| Full-detail node guard | 1,500 projected nodes | Warning callout + explicit **Load full detail** press (C-2) |
| Layout quality degradation | 100 nodes (`LAYOUT_NODE_BUDGET`, unchanged) | fCoSE drops to `quality: "default"`, `randomize: false` — existing behaviour |
| Badge fetch budget | 4 pages × 500 items = 2,000 per collection | Badge-coverage callout + footnote disclosure (C-1) |
| Server topology build | p95 < 1 s at enterprise size (646 ms measured) | The cached source acquisition duration is published. Above 3 s, full detail requires confirmation; an in-flight request retains context, reports elapsed time, and offers explicit Cancel. No automatic client-side timeout is introduced. |
| Hybrid network reuse | 5 minutes from completed ARG acquisition | Summary, Full detail, and drawer requests in one operator workflow reuse the same completed observation; freshness remains explicit through the response evidence timestamp. |
| Refetch debounce | 400 ms | At most one refetch per loader per window (C-6) |
| Drill-down page size | 50 rows | `TablePagination` (C-2) |
| Node-count disclosure | always | Footnote reports `{rendered} of {total}` even when equal |
