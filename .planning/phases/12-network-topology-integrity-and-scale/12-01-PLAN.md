<objective>
Close the cross-subscription authorization leak across every scope call site, and prove it end to end from the
network service through the REST routers to the agent/MCP consumers. This is the phase's security gate: no
later plan may merge until this one is green.

Purpose: `NetworkScope.filter_snapshot()` rebuilds the snapshot with `replace()` enumerating 14 collections while
`NetworkSnapshot` has 15. The omitted collection is `private_link_resources`, which `NetworkGapAnalyzer`
iterates directly, so a caller scoped to one subscription receives high-severity `missing_private_endpoint`
gaps naming other subscriptions' Key Vaults, storage accounts, and Fabric capacities — complete with ARM
resource IDs and subscription GUIDs. RESEARCH reproduced this by executing the shipped code. It is an ASVS V4
access-control defect (`.planning/config.json`: `security_enforcement: true`, `security_block_on: high`) and it
reaches the web UI, the agents, and MCP through the same seam. Locked decision 1 makes it the first tracer.

Output: A single scope enforcement point covering all 15 collections plus semantic relationships, applied
identically at every construction site, with failing-first regression coverage of the previously untested
`scoped()` seam.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator scope selection -> network analysis | The requested subscription/resource-group scope is the authorization boundary; everything past it must be filtered |
| network service -> REST routers | Routers trust the scoped service to have already filtered; they do not re-filter |
| network service -> agents / MCP relay | Agent tools call the same `scoped()` seam, so a seam defect is a multi-surface disclosure |

| T-12-02 | Information Disclosure | `NetworkIntelligenceService.scoped` dropping semantic relationships, then re-adding them unfiltered | high | mitigate | Forward relationships through a scope-aware endpoint filter, not verbatim (Task 1) |
