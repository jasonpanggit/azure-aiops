<objective>
Make the snapshot worth projecting: normalise identifiers at the model boundary, count what the projection drops
instead of discarding it silently, restore honest freshness, derive flow-log provenance from data, and make each
unresolved peer state why it is missing.

Purpose: RESEARCH schedules this immediately after the scope gate and explicitly warns against running it in
parallel — it touches the same files and tests as plan 12-01. It exists because the entire class of "missing
subnet / DNS / Fabric links" and "stale sync data" user reports is currently unfalsifiable: `_has_resource` is an
exact-case membership test against uniformly-lowercased node ids, `add()` returns early on a miss with no counter,
`Subnet.private_endpoint_ids` is the only id collection not lowered, `_load_network_service()` discards the
freshness value it just computed, and the flow-log banner is a constant. RESEARCH reproduced each of these by
executing the shipped code.

This plan also implements the server side of `12-UI-SPEC.md` C-10. That contract attributes peer-resolution
derivation to `_scoped_topology`, which plan 12-01 deletes as a duplicate enforcement point; the derivation
therefore lands on the surviving `scoped()`/`TopologyBuilder` seam. This is a deliberate, recorded deviation from
the letter of the UI spec that preserves its intent and locked decision 1.

Output: a normalised, diagnosable, honestly-timestamped snapshot whose projection reports its own losses.
</objective>

  <files>src/network/topology.py, src/network/service.py, tests/test_network_topology.py</files>
  <behavior>
    - Given an unscoped snapshot containing VNet-A in scope, VNet-B ingested but excluded by the active scope, and a peering from VNet-A to never-ingested VNet-C, the scoped topology response emits an `unresolved_peers` array containing exactly VNet-B marked excluded-by-scope and VNet-C marked not-ingested (C-10 AC-1).
    - The resolution field only ever holds one of three declared values; a fixture asserting the full enumeration fails if a fourth string is emitted (C-10 AC-2).
    - With an empty scope, no entry is marked excluded-by-scope (C-10 AC-3).
    - `unresolved_peer_vnet_ids` is still present in the same response with unchanged membership, so an existing agent, MCP, or export consumer reading only that key is unaffected (C-10 AC-4, locked decision 6).
    - Widening the scope to include VNet-B removes it from the unresolved set or marks it observed, and it renders with its real kind (C-10 AC-11).
  </behavior>
  <action>
    Implement the server side of `12-UI-SPEC.md` C-10 on the surviving scope seam. Plan 12-01 deleted
    `_scoped_topology`, which the UI spec names as the derivation site; derive here instead from the
    `scoped()`/`TopologyBuilder` path so there remains exactly one scope enforcement point. Record this deviation
    in the SUMMARY.

    Add an `unresolved_peers` array to the topology payload where each entry carries the peer VNet id, a required
    resolution selector, and an optional subscription id. The selector takes exactly three values: not-ingested
    when the id is absent from the unscoped snapshot VNets; excluded-by-scope when it is present in the unscoped
    snapshot but fails the scope predicate; observed when it survives scoping. When the scope is empty, the
    excluded-by-scope value can never be produced.

    The server must never guess. If the unscoped snapshot is not reachable from the scoped call, emit
    not-ingested only when that is provable; otherwise omit the peer from `unresolved_peers` entirely and let the
    client fall back to its unknown state. A guess must never be encoded as a resolution — that is precisely the
    false statement this contract exists to remove, and it is a scope-isolation honesty defect under locked
    decision 1.

    Retain `unresolved_peer_vnet_ids` unchanged alongside the new array. Locked decision 6 and the UI spec's
    non-goals both forbid removing it; `unresolved_peers` is strictly additive.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ontology rows -> network models | Externally-sourced identifiers with no casing guarantee cross into a uniformly-lowercased model space |
| topology projection -> operator-facing diagnostics | Drop counters and warnings must describe loss without re-disclosing the identifiers scope filtering removed |
| unscoped snapshot -> scoped response | Peer resolution needs a fact about the unscoped estate without leaking unscoped resource detail |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-64 | Information Disclosure | Dropped-relationship diagnostics echoing out-of-scope ARM ids | high | mitigate | Counters record relationship-type keys and integer counts only; no identifier is logged or returned (Task 1, ASVS V7) |
| T-12-65 | Information Disclosure | Peer-resolution derivation exposing unscoped VNet detail to a scoped caller | high | mitigate | Only the peer id already present in an in-scope peering plus a three-value selector are emitted; no unscoped resource properties cross the boundary (Task 3) |
| T-12-66 | Repudiation | Freshness silently degrading to unknown, so an operator cannot tell a fresh topology from a week-old one | medium | mitigate | Snapshot-level stamp threaded through the loader; band asserted never-unknown when a stamp exists (Task 2) |
| T-12-13 | Tampering | Flow-log provenance asserting analysis that never runs | high | mitigate | Three-state provenance including the ingested-but-unanalyzed state, plus the analyzer observation seam (Task 2, pitfall P-7) |
| T-12-14 | Tampering | Dangling resolution relationships written to entities that do not exist | medium | mitigate | Emit the link only when the parent zone is present; record a normalisation warning otherwise (Task 2) |
| T-12-15 | Spoofing | Case-variant ARM identifiers evading membership tests and hiding real edges | medium | mitigate | Normalise once at the model boundary and casefold both sides in the membership test (Task 1) |
| T-12-SC | Tampering | npm/pip/cargo installs | low | accept | RESEARCH §Package Legitimacy Audit records zero package installs for this phase; this plan adds none |
