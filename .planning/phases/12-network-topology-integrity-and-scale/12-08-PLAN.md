<objective>
Make the network page tell the truth about how much it loaded, let a policy edit change what is on screen without
a reload, and derive freshness and flow-log provenance from data instead of constants.

Purpose: the metric cards render the length of arrays the server capped at its default limit while the summary
block beside them carries the real totals, so at enterprise scale a card freezes at the cap while the underlying
summary says several hundred. The tabs render the same truncated lists with no pagination control. Policy
mutations update local component state only, so badges and gaps keep showing pre-edit results until a full reload.
The header renders a fixed flow-log claim regardless of observed data, and the freshness segment is filtered out
entirely when no stamp is present — an absence, not a disclosure.

This plan owns the page shell, the service client, the shared types, and the evidence bar. The canvas, drawer, and
export surfaces are plans 12-09 and 12-10, so no file is shared across those waves.

Output: honest page-level counts and coverage, a working policy round-trip, and data-derived provenance.
</objective>
