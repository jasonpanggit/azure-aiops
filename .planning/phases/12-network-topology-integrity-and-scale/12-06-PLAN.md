<objective>
Project private-link resources onto the canvas so that Microsoft Fabric capacities, Azure AI Foundry accounts, and
every other in-scope private-link candidate become visible nodes, and so that every finding raised against them
has something to attach to.

Purpose: the projection extends nodes from seventeen collections but never from the private-link collection.
RESEARCH proved by execution that a snapshot with a Fabric capacity and an AI Foundry account renders zero nodes
for them while `counts` reports two. The only way such a resource reaches the canvas today is by already being
targeted by a NIC, private endpoint, or load balancer — which means the resources missing a private endpoint,
precisely the ones gap analysis flags high-severity, are exactly the ones that cannot appear. The result is an
orphaned finding: a red gap whose resource id matches no node, so it can never be badged and never opened in the
drawer. This is one of three independent causes of the reported "red-dot findings not appearing in drawer".

This plan runs after the scope gate — projecting before scoping was fixed would have widened the disclosure onto
the canvas — after the correctness cluster, so identifiers are already normalised, and after the Fabric semantics
checkpoint, so the disposition for the Fabric finding is known.

Output: private-link nodes with mapped entity types, de-duplicated, icon-backed where an official glyph exists.
</objective>
