<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser → snapshot API | Untrusted page state, filters, evidence rows, and question cross the boundary. |
| API → governed tools/providers | Specialist requests must remain inside the caller’s effective scope and allowlist. |
| API → Foundry | Curated evidence leaves the service; Foundry must not receive secrets or unbounded raw data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-09-01 | Tampering | PageSnapshot validation | high | mitigate | Strict typed/versioned models, size/count limits, server-derived scope comparison, and evidence-reference validation. |
| T-09-02 | Information disclosure | Tool and Foundry context | high | mitigate | Reuse effective `ReadScope`, allowlisted tools, recursive filtering, bounded curated context, and no secrets in snapshots. |
| T-09-03 | Elevation of privilege | Finding/action handoff | high | mitigate | Mark hypotheses and stale/partial evidence explicitly; require human approval and server-side scope checks before any action handoff. |
| T-09-04 | Denial of service | Reassessment loop | medium | mitigate | Enforce step, concurrency, retry, payload, and wall-clock budgets; cancel outstanding work on timeout. |
| T-09-SC | Tampering | npm/pip/cargo installs | high | accept | No package installation is planned; existing dependencies only. |
</threat_model>
