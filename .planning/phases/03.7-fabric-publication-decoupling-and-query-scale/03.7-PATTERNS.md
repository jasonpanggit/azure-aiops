## Pattern Assignments

### 1. Inventory Product Manifest

**Expected placement**

- Generic immutable contracts: `src/fabric/product_manifest.py`.
- Inventory-owned manifest construction: extend
  `src/intelligence/inventory/fabric_publication.py`; do not teach the generic
  Fabric module which inventory datasets belong together.
- Inventory schema and logical-to-physical mapping remain in
  `src/intelligence/inventory/fabric_contracts.py`.

**Expected symbols**

```python
@dataclass(frozen=True)
class ProductTableManifest: ...

@dataclass(frozen=True)
class DomainProductManifest: ...

@dataclass(frozen=True)
class DomainProduct:
    manifest: DomainProductManifest
    tables: Mapping[str, Sequence[Mapping[str, Any]]]
```

The internal names are discretionary, but the manifest must carry product ID,
product generation, atomic group, manifest/product schema versions, source
generation(s), declared tables, row counts, content/schema hashes, quality,
lineage, compatibility, and a deterministic overall content hash.

**Candidate pattern** — `src/ontology_discovery/publisher.py:46-56`:

```python
@dataclass(frozen=True)
class OntologyGenerationCandidate:
    generation_id: str
    source_generation: str
    entities: tuple[dict[str, Any], ...]
    relationships: tuple[dict[str, Any], ...]
    proposal_lineage: tuple[str, ...]
    decision_lineage: tuple[str, ...]
    policy_version: str
    schema_version: str
```

Copy the frozen candidate style and make all sequence fields immutable before
hashing. Do not pass a mutable `dict[str, list]` as the authoritative manifest.

**Per-table contract pattern** —
`src/intelligence/inventory/fabric_contracts.py:21-27`:

```python
@dataclass(frozen=True)
class InventoryFabricContract:
    logical_name: str
    table_name: str
    schema: pa.Schema
    required_fields: tuple[str, ...]
    identity_fields: tuple[str, ...]
    source_status_table: str = ""
```

`ProductTableManifest` should reference these inventory-owned logical and
physical names rather than duplicating schema knowledge in the publisher.

**Deterministic hash pattern** —
`src/ontology_discovery/publisher.py:472-526`:

```python
def _content_hash(value: object) -> str:
    body = json.dumps(
        value,
        sort_keys=True,
        separators=(",", ":"),
        ensure_ascii=False,
    ).encode()
    return hashlib.sha256(body).hexdigest()
```

Normalize rows and metadata before hashing. Exclude explicitly documented
volatile fields only; never remove source generation, lineage, quality, or
compatibility from product identity.

**Inventory atomic group**

Use the exact five logical datasets already owned by
`src/intelligence/inventory/combine.py:20-28`:

```python
_INVENTORY_DATASETS = (
    "inventory/os_observations",
    "inventory/source_status",
    "inventory/software_observations",
    "inventory/software_source_status",
    "inventory/resource_observations",
)
```

The inventory product builder should receive the already-computed five-table
mapping from `InventoryPipeline`/combined publication. It must not invoke
`InventoryDatasetMapper`, Exposure projection, ontology synchronization, or UI
composition.

**Validation pattern** —
`src/intelligence/inventory/fabric_contracts.py:313-354`:

```python
for index, row in enumerate(rows):
    missing = [
        field for field in contract.required_fields
        if _missing(row.get(field))
    ]
    ...
    assessment_fields = sorted(set(row) - set(contract.schema.names))
```

Build the manifest only after each declared dataset passes this domain
validation. The generic publisher must independently verify declaration,
count, hashes, and schema identity, but must not recreate inventory quality
rules.

**Anti-patterns**

- Do not extend `ontology.publication_manifest.PublicationManifestStore`; it
  tracks projection disposition, not immutable table transactions.
- Do not put page, route, drawer, Copilot, or `PageSnapshot` names in a product.
- Do not infer the table list by iterating every available dataset. Publication
  is declaration-driven.
- Do not write the same rows under logical and physical aliases by default.
  Compatibility duplication must be named, gated, and metered.

**Generation-qualified schema migration artifact**

Plan 03 modifies `src/intelligence/inventory/fabric_contracts.py` directly
rather than assigning the change to `inventory/pipeline.py`. The owning symbols
are `INVENTORY_PRODUCT_GENERATION_FIELD`,
`INVENTORY_PRODUCT_SCHEMA_VERSION`, `InventoryProductRelationStrategy`,
`InventoryProductSchemaMigration`,
`generation_qualified_inventory_contracts(...)`, and
`plan_inventory_product_schema_migration(...)`.

Compose two existing analogs:

1. `InventoryFabricContract` remains the inventory-owned logical/physical
   schema authority and adds the non-null `product_generation_id`
   discriminator to all five shadow relation schemas.
2. `AuthoritativeDatasetPublisher.stage_generation(...)` supplies the
   non-destructive ordering: stage immutable relation data, verify every
   schema/count/hash, write the completeness marker last, then initialize the
   namespaced pointer by conditioned CAS.

The migration descriptor must identify source generation, target product
generation, all five source/target relations, schema version, predecessor
pointer, hashes, and retained-history policy. It never rewrites or deletes the
legacy relation set during shadow/canary.

### 2. Generic Product Publisher

**Expected placement**

`src/fabric/product_publisher.py`, with product-scoped storage roots/pointers.
It may compose `DeltaWriter`, `OneLakeDocumentStore`, schema lookup, and
`GenerationPointerConditions`, but domain projectors stay outside it.

**Expected symbols**

```python
class ProductPublicationSafetyError(RuntimeError): ...

@dataclass(frozen=True)
class ProductStageResult: ...

class FabricProductPublisher:
    def stage(self, product: DomainProduct, *, conditions, owner_id, fence): ...
    def verify(self, stage: ProductStageResult): ...
    def activate(self, stage: ProductStageResult): ...
    def publish(self, product: DomainProduct, ...): ...
    def rollback(self, target_generation_id: str, ...): ...
```

The publisher owns only: declared-table validation, generation-qualified
staging, persisted count/hash/schema verification, durable audit/receipt,
product pointer CAS, post-check handling, and retained-generation rollback.

**Immutable stage pattern** —
`src/storage/datasets.py:189-226`:

```python
def stage_generation(...):
    if self.generation_exists(generation):
        raise DocumentConflictError(
            f"generation {generation} is immutable and already exists"
        )
    ...
    for name, payload in artifacts:
        self._documents.create_only(f"{base}/{name}", payload)
    # The manifest is the completeness marker and is deliberately last.
    self._documents.create_only(f"{base}/manifest.json", manifest)
```

Adapt this ordering to product metadata: stage physical table generations,
write verification/compatibility/audit artifacts, and make the complete product
manifest the final immutable-stage marker. A retry may accept an existing stage
only after byte-for-byte verification.

**Conditional promotion pattern** —
`src/storage/datasets.py:299-335`:

```python
current = self.assert_pointer_conditions(conditions)
if current.pointer is not None and fence <= current.pointer.fence:
    raise DocumentConflictError("promotion fence is not monotonic")
...
if current.etag is None:
    written = self._documents.create_only(_POINTER_NAME, pointer.to_payload())
else:
    written = self._documents.replace_if_match(
        _POINTER_NAME,
        pointer.to_payload(),
        expected_etag=current.etag,
    )
```

Copy ETag/predecessor/fence behavior. Use a **namespaced product pointer root**;
do not reuse ontology's hard-coded `current.json` at the same storage root.

**End-to-end publication sequence** —
`src/ontology_discovery/publisher.py:80-255`:

1. authorize publisher/checkpoints;
2. guard cancellation and lease;
3. assert pointer preconditions;
4. validate candidate;
5. stage immutable content;
6. verify persisted content;
7. persist audit intent;
8. recheck lease, pointer, and validation immediately before CAS;
9. conditionally promote;
10. run post-checks and write receipt;
11. roll back with a newer fence if post-checks fail.

The new publisher should copy this sequence, not merely its class shape.

**Stale-writer and rollback test pattern** —
`tests/test_ontology_generation_publication.py:237-273`:


| Inventory | New generic product manifest/publisher tracer; all five inventory datasets advance together. |
| Exposure Gold | Keep `ExposureGoldFabricPublisher.stage()` and `.activate()` unchanged; its five Gold tables plus generation metadata remain one generation. |


Do not replace this with the generic pointer during Phase 03.7.

**Exposure rollback test to retain** —
`tests/test_vulnerability_pipeline.py:505-667`:

- `test_gold_activation_refuses_pointer_change_after_staging`

**Anti-patterns**

- Do not compute a projector result under the product publisher lease.
- Do not restore several mutable “current” tables to implement reader rollback.
- Do not promote before persisted verification and durable audit.
- Do not share one active pointer across unrelated products.
- Do not wrap Exposure Gold or ontology in a second pointer transaction.

### 4. Production Status-Only Probe and Compatibility-Reader Gate

**Expected placement**

- Provider/publication status loading and reader selection:
  `src/api/runtime.py`.
- Last-known-good state container: preserve `src/api/providers.py`.

- Low-cardinality compatibility-use metric: `src/fabric/telemetry.py` or

**Production status-only probe**

No new domain service should be built inside `/health` or `/ready`. A compact
status reader may read an already-cached pointer/status projection during the
background refresh, then publish that sanitized state into `ProviderRuntime`.
Probe handlers serialize that in-memory state only.

**Runtime metadata change** —

### 5. Fabric SQL Inventory Query Adapter

**Scope-first compiler pattern** —
`src/api/exposure_query.py:866-957`:

```python

    predicates, parameters, "[connection_id]",

    "WITH [scoped] AS ("
    f"SELECT {projection} FROM {table} WHERE {where_sql}"
    ")"

count_sql = (
    f"{scoped_cte} "
    "SELECT COUNT_BIG(...) AS [total_count] FROM [scoped]"
```

For inventory, compile in this order:

1. validate a server-derived `Scope`;
2. capture one active inventory product generation;
3. compile every effective scope dimension into the base relation;
4. fail closed for a constrained dimension the product cannot represent;
5. bind product generation;
6. bind family and resource-type filters;
7. count the filtered relation;
8. order by `family ASC, resource_id ASC`;
9. apply the existing bounded offset/limit contract in SQL.

Do not add a cursor to the public API in this phase. Offset compatibility is
locked; a complete batch scan may use an internal generation-pinned
continuation.

**Bounded transport pattern** — `src/fabric/sql_endpoint.py:243-276`:

```python
cursor.execute(sql, *parameters)
...
rows = cursor.fetchmany(max_rows + 1)
if len(rows) > max_rows:
    raise FabricSqlQueryLimitError(
        f"Fabric SQL query exceeded the {max_rows}-row limit"
    )
```

Use `max_rows=1` for count/direct lookup, `limit + 1` for a page, and a bounded
registered-family/status maximum for availability. All values are bound;
identifiers come only from strict allowlists.

**Production SQL relation**

Build one canonical relation from:

- `inventory_os_observations` projected to family `os`;
- `inventory_resource_observations` projected to its stored family (currently
  PaaS and future registered families).

VM/Arc must not be duplicated from resource observations. Returned rows must
match `InventoryService.resources()`'s consumer-safe shape, including lossless
PaaS `properties`/`tags` decoded only for returned rows. Raw
`provider_payload_json` and internal ordering/generation columns must not leak.

Before implementation, resolve the costly physical-storage decision identified

**Direct lookup**

the canonical resource ID. Return `None` for zero rows. Never run a second

**Availability**

```python
    "logical_dataset": ...,
```

**Containment**

### 7. Telemetry, Shadow, Canary, and Rollback

**Telemetry pattern** — `src/fabric/telemetry.py:8-48`:

```python
self.duration = meter.create_histogram(...)
self.rows_processed = meter.create_counter(...)
...
def record_table(self, table: str, result) -> None:
    attributes = {"table": table}
```

Add low-cardinality measurements for:

- product projection duration;
- stage/verify/promotion duration;
- declared and published table count;
- product outcome and product ID (allowlisted values only);
- query operation/duration/rows materialized;
- selected adapter;
- compatibility-reader use;
- shadow outcome/reason code.

Never attach source IDs, resource IDs, scope values, manifests, raw exception
text, or provider payloads.

**Shadow comparison**

Compare legacy/new readers at the same source/product generation for:

- canonical resource identity and safe projection;
- total;
- family availability and warnings;
- stable page order;
- direct lookup;
- containment.

Treat scope widening, count mismatch, duplicates/omissions, availability drift,
or distinguishable out-of-scope lookup as cutover blockers.

**Rollback**

- Reader rollback selects the prior reader mode.
- Product rollback CAS-selects a retained product generation.
- It must not delete source observations, product history, ontology
  generations/audits, or Exposure Gold generations.
- Inventory rollback must not move ontology or Exposure pointers.

**Benchmark pattern**

`scripts/benchmark_fabric_product_publication.py` should copy the deterministic
reporting structure from `scripts/benchmark_exposure_read_model.py`: separate
local deterministic evidence from deployed Fabric evidence, use warmups plus
20 same-generation measurements, report p50/p95 duration and table count, and
never claim deployed improvement from the local fixture.

## Shared Patterns

### Scope Validation

**Source:** `src/intelligence/inventory/read_port.py:89-92`

```python
if scope is None or not hasattr(scope, "matches") or not hasattr(scope, "to_dict"):
    raise TypeError(
        "InventoryReadPort requires a server-derived effective scope"
    )
```

Apply before adapter/query compilation. Request parameters may narrow a
server-derived scope but never create authorization.

### Bound Values and Allowlisted Identifiers

**Source:** `src/fabric/sql_endpoint.py:88-104,243-276` and
`src/api/exposure_query.py:866-957`.

All values use ODBC parameters. Table, schema, projection, filter, and order
identifiers come from code-owned allowlists and are bracket-quoted.

### Last-Known-Good Runtime State

**Source:** `src/api/providers.py:98-407`.

Background refresh atomically replaces successful providers. Failed refreshes
retain the previous instance and mark health degraded/stale; requests and
probes perform no loader I/O.

### Error Handling

- Manifest/domain validation: raise `ValueError` before staging.
- Availability/configuration: use a typed `...UnavailableError`.
- Stale writer/storage conflict: translate `DocumentConflictError` into a
  typed publication safety error without exposing storage details.
- API routes continue through existing `ApiError` translation/envelope logic;
  do not return ad hoc error payloads.
- Compatibility/local truncation must be explicit, never represented as a
  successful exact total.

### Stable Test Doubles

- Product lifecycle: `_publisher`, `_candidate`, and `_publish` fixtures from
  `tests/test_ontology_generation_publication.py:65-131`.
- Exposure preservation: `_gold_server_datasets` and local
  `OneLakeDocumentStore`/`DeltaWriter` setup from
  `tests/test_vulnerability_pipeline.py:490-667`.
- Inventory response shape: `_service` from
  `tests/test_inventory_read_port.py:21-82`.
- Fabric publication: `_InventorySource`, `_LogsSource`, and
  `refresh_inventory` from `tests/inventory_harness.py:12-84`.
- SQL work bounds: `PageReader` from
  `tests/test_exposure_api_performance.py:35-57`.
- Runtime no-I/O: call-recording provider fixtures from
  `tests/test_api_providers.py:99-225`.

## Anti-Pattern Checklist

Planner tasks should explicitly guard against all of the following:

1. `InventoryDatasetMapper.load()` reachable from production request or probe
   paths.
2. `/ready` calling `ProviderRuntime.refresh(...)`.
3. `_runtime_metadata()` constructing a semantic engine.
4. Product publication iterating undeclared tables.
5. Inventory publication triggering broad `FabricSyncService.sync()`.
6. Any product publisher running domain projectors.
7. A shared pointer for unrelated products.
8. Replacing Exposure Gold stage/activate/retention semantics.
9. Replacing ontology immutable stage/audit/fence/CAS/rollback semantics.
10. SQL reads without product-generation and scope predicates.
11. Fixed `10_000` full-estate scans.
12. Filtering/counting/paging after materialization.
13. Unscoped existence checks.
14. Availability inferred from a filtered page.
15. Silent production fallback from Fabric SQL to Delta/local.
16. Duplicate compatibility writes without a named consumer and usage
    telemetry.
17. Publishing PageSnapshot or UI-specific tables.
18. Logging scope/resource IDs, payloads, manifests, or dynamic exception text
    as telemetry dimensions.
