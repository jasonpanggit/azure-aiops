<objective>
Make `_check_approval_gate` (the one function shared by `execute()`,
`retry()`, and `plan_eligibility()`) the single, real enforcement point for
(a) per-role approval-requirement satisfaction and (b) requester-versus-
approver separation of duties, for BOTH the patch and Defender-configuration
action families (D-01, D-02). Today it only checks "does *some* approved
decision exist, matching action_version, unexpired" (CR-04: "one decision
suffices") and separation of duties is enforced only inside
`PatchingService.trigger()` -- meaning the Defender-configuration submit
path (`self._defender_configuration.submit(...)`, called with no
requester/approver at all) has zero self-approval protection today
(CR-04/CR-05).

Purpose: this is the phase's central correctness fix -- "governed remedy
execution enforces one evidence-sensitive approval policy... with
machine-checkable requirements... and explicit demo self-approval" is not
true until this function checks it.
Output: `_check_approval_gate` refuses on unmet per-role requirements and
on undisclosed self-approval, for both families identically; a passing
self-approved execution durably records that fact on the decision.
</objective>
