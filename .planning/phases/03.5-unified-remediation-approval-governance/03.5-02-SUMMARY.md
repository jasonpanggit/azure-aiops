# Phase 03.5 Plan 02: Distinct approve/operate RBAC action and dependency Summary

Added a new `approve` RBAC action and `ROLE_APPROVER` role, deliberately excluded from `operate`'s satisfying-role set and vice versa, plus the matching `ApprovePrincipal`/`require_approve` FastAPI dependency pair — the foundation Plan 03.5-06 switches `record_remediation_decision` onto.

## What Was Built

- **`src/api/rbac.py`**: `ROLE_APPROVER = "approver"` added to `ROLES`; `ACTION_APPROVE = "approve"` added to `ACTIONS`. `_ACTION_ROLES` updated: `ACTION_READ` now includes `ROLE_APPROVER` (every role can still read); `ACTION_OPERATE` unchanged (`{ROLE_OPERATOR, ROLE_ADMIN}` — `ROLE_APPROVER` excluded); `ACTION_APPROVE: {ROLE_APPROVER, ROLE_ADMIN}` (new — `ROLE_OPERATOR` excluded, the deliberate tightening); `ACTION_WRITE` unchanged.
- **`src/api/dependencies.py`**: `require_approve(principal, context)` and `ApprovePrincipal = Annotated[Principal, Depends(require_approve)]` added immediately after the existing `require_operate`/`OperatePrincipal` pair, identical shape.
- **`tests/test_api_primitives.py`**: Five new `TestRbac` tests — `test_approver_may_approve_but_not_operate_or_write`, `test_operator_may_operate_but_not_approve` (the one deliberate compatibility break — an operator-only principal can no longer approve), `test_admin_may_approve_and_operate`, `test_grant_accepts_approver_role`, `test_effective_scope_narrows_approve_to_granted_subscription`.
