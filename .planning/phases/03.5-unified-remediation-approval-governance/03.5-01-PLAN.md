  <files>src/intelligence/remediation/action_version.py, src/intelligence/remediation/remediation_generator.py, tests/test_remediation_action_version.py</files>
  <behavior>
    - `action_version_for(*, action_id, target_id, scope, evidence_citations) -> str`
      returns a 16-hex-char sha256-derived string.
    - Same inputs (including citation order) → identical output across two
      separate calls and across two module-fresh processes (no in-memory
      caching, no randomness).
    - Changing only one evidence citation's `source_id` or `observed_at`
      changes the output.
    - Changing `scope` (e.g. a different sorted patch-id list, or a
      different Defender recommendation string) changes the output even
      when `target_id`/`action_id`/evidence are unchanged.
    - Passing the current wall-clock time nowhere in the function signature
      or body is a hard invariant (D-04: "never include query/current
      wall-clock time") — assert this by calling the function twice with a
      monkeypatched `datetime.now`/`time.time` returning different values
      and asserting identical output.
    - An empty `evidence_citations` list produces a stable, distinct digest
      (not equivalent to any nonempty-citation input) — generalizes the
      existing `RemediationGenerator._stable_evidence_digest` sentinel
      behavior (src/intelligence/remediation/remediation_generator.py:226-249).
  </behavior>
  <action>
    Create `src/intelligence/remediation/action_version.py` with a single
    public function `action_version_for(*, action_id: str, target_id: str,
    scope: Any, evidence_citations: list[dict[str, Any]]) -> str`. Move
    `RemediationGenerator._stable_evidence_digest` verbatim into this module
    as a private `_stable_evidence_digest(citations)` helper (same sorted
    `f"{source_type}:{source_id}:{observed_at}"` join, same
    `__no_evidence__` sentinel for empty input) — this is the one legitimate
    reuse of "evidence content timestamp" in this codebase (`observed_at` is
    the citation's own observation time, not `datetime.now()`). Serialize
    `scope` via `json.dumps(scope, sort_keys=True, separators=(",", ":"),
    default=str)` so it accepts a list, dict, or scalar without raising.
    Canonicalize `{"action_id": action_id, "target_id": target_id, "scope":
    <serialized scope>, "evidence_digest": _stable_evidence_digest(...)}`
    through the same sorted-key JSON serialization, then
    `hashlib.sha256(...).hexdigest()[:16]`, matching the existing 16-char
    convention used everywhere else in this module family (D-04, per
    CONTEXT.md "Evidence Versioning" and REVIEW recommendation 4's
    `action_version_for(...)` helper).
    Update `RemediationGenerator.generate()`
    (src/intelligence/remediation/remediation_generator.py:99-101) to call

    scope={"execution_steps": action.get("execution_steps"), "rollback_actions": action.get("rollback_actions")},

    `hashlib.sha256(f"{action['action_id']}|...")` construction; delete the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Decision-store write path | Only server code (never a request body field) may set `self_approved`/`self_approval_policy_id`/`approver_roles`. |
| action_version computation | Feeds directly into approval staleness; must not be influenced by caller-supplied wall-clock time or it becomes forgeable/replayable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.5-01 | Tampering | `RemediationDecisionRequest` (API model, later plan) | high | mitigate | `self_approved`/`self_approval_policy_id`/`approver_roles` are never accepted as request fields anywhere in this codebase — `record_self_approval()` is the sole write path, called only from server-side gate logic (enforced in Plan 03.5-05), not from any Pydantic model. |
| T-03.5-02 | Repudiation | `action_version_for()` | medium | mitigate | Excluding wall-clock time from the digest means a durable decision's staleness can always be recomputed identically from stored evidence later, for audit — verified by Task 3's monkeypatched-clock test. |
| T-03.5-03 | Tampering | `RemediationDecisionStore.record_self_approval()` | medium | mitigate | CAS-guarded (`expected_revision`) update scoped to exactly one record's two fields; every other field and every other record is read back byte-identical, verified by test. |
