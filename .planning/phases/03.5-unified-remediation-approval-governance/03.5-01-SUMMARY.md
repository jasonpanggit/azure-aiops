# Phase 03.5 Plan 01: Shared action_version_for(), ApprovalEngine.policy_version, and durable decision-store facts Summary

One shared, deterministic, evidence-sensitive `action_version_for()` helper now backs every remediation planner; `ApprovalEngine` gained a stable `policy_version`; `RemediationDecisionStore` durably records `approver_roles`/`approval_policy_version` on every new decision and `self_approved`/`self_approval_policy_id` exclusively via a new CAS-guarded `record_self_approval()`.

## What Was Built

- **`src/intelligence/remediation/action_version.py`** (new): `action_version_for(*, action_id, target_id, scope, evidence_citations) -> str` — a 16-hex-char sha256 digest over action identity, target identity, an action-family-specific `scope` payload, and a stable evidence-citation digest (`_stable_evidence_digest`, moved verbatim from `RemediationGenerator`). Deterministic across processes; wall-clock-blind (verified by a monkeypatched-clock test); evidence-content-sensitive (citation `source_id`/`observed_at` changes flip the digest); an empty citation list produces a stable, distinct sentinel digest.
- **`RemediationGenerator.generate()`** now calls the shared helper in place of its own inline `hashlib.sha256(...)` construction; the now-unused `_stable_serialize`/`_stable_evidence_digest` staticmethods and the now-unused `json` import were removed.
- **`ApprovalEngine.policy_version`** (new cached property): a stable hash over `self.policies`, computed by sorting each policy's own canonical JSON serialization (so instance-construction order never affects the version) — order-independent, change-sensitive (verified by a dedicated test).
- **`RemediationDecisionStore`** bumped to schema `1.1.0`: `append()` gained `approver_roles: list[str] = ()` and `approval_policy_version: str = ""` keyword parameters (normalized: deduped, casefolded, sorted); every appended record also carries `self_approved: False` and `self_approval_policy_id: ""` by construction — neither is settable via `append()`. A new `record_self_approval(decision_id, *, policy_id, now=None)` is the sole write path for those two fields: CAS-guarded (same read/mutate/write/retry-3x pattern as `append()`), idempotent (a second call with the same `policy_id` on an already-marked record is a no-op, no revision bump), and raises `ValueError` on an unknown `decision_id`. `_read_state()` backfills all four new fields with safe defaults for any legacy document lacking them.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `ApprovalEngine.policy_version` was order-dependent on first implementation**
- **Found during:** Task 3 (writing the order-independence test)
- **Issue:** `json.dumps(self.policies, sort_keys=True, ...)` sorts dict *keys* within each policy but not the *list order* of policies themselves, so two engines built from the same policies in different construction order produced different version hashes — failing the explicit "identical policy lists (any input order) yield the identical version string" requirement.
- **Fix:** Serialize each policy to its own canonical JSON string first, sort that list of strings (stable since every policy has a unique `policy_id`), then hash the sorted list.
- **Files modified:** `src/intelligence/remediation/approval_engine.py`
- **Commit:** none (no commits made this session)
