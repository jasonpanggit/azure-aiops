# Phase 03.5 Plan 04: Live patch/Defender planners on the shared action_version and ApprovalEngine-shaped requirements Summary

`LiveRemediationPlanner._plan()` (patch) and `_configuration_plan()` (Defender) now both compute `action_version` via the shared `action_version_for()` helper and both emit `ApprovalEngine.requirements()`-shaped `approval_requirements` rows — replacing two divergent inline hash formulas and an ad hoc `{role, reason}` list with the same machine-checkable shape the Fabric/catalog planner already produces.

## What Was Built

- **`_plan()` (patch)**: `action_version` is now `action_version_for(action_id=..., target_id=canonical_resource_key(target_id), scope=sorted(missing_kbs), evidence_citations=...)`. The method's `evidence_citations` list construction was moved earlier so both the version call and the returned dict reference the identical list object (no duplicate construction, no drift).
- **`_configuration_plan()` (Defender)**: `action_version` is now `action_version_for(action_id=..., target_id=resource["id"], scope=recommendation, evidence_citations=...)` — this closes a real prior gap where the old formula (`{action_id, target, recommendation, assessment_id}`) never included `last_assessed_at` at all, so an assessment-timestamp change was previously undetectable; it is now carried via the evidence citation's `observed_at`.
- **`LiveRemediationPlanner.__init__`** gained `patch_approval_engine`/`configuration_approval_engine` keyword parameters (both optional, each defaulting to its own single-policy `ApprovalEngine` — `_DEFAULT_PATCH_APPROVAL_POLICIES` role "Change approver", `_DEFAULT_CONFIGURATION_APPROVAL_POLICIES` role "Security Response Owner"). Two separate engines (not one shared multi-policy engine) prevent cross-family role bleed, since `ApprovalEngine` has no action-id filter of its own.
- **`approval_requirements`** in both plan dicts is now `self._patch_approvals.requirements(...)` / `self._configuration_approvals.requirements(...)`, replacing the old single-row `{"role": ..., "reason": ...}` shape with the full `policy_id`/`role`/`stage`/`status`/`approval_evidence_required`/`approval_recorded` shape. Resource shim `{**resource, "business_criticality": resource.get("criticality", "")}` bridges the patch resource dict's `"criticality"` key to `ApprovalEngine.requirements()`'s expected `"business_criticality"` key without renaming the source dict.
