<objective>
Close the Phase 2 API gap: `src/api/app.py` mounts no `remediation` router, so nothing under `/api/v1/remediation/plans/*` exists yet even though the full business logic (`RemediationPlanner`, `PlanRepository`, `ApprovalEngine`, `BusinessDecisionEngine`) has existed since Phase 2. This plan creates a thin, read-only HTTP layer over that existing logic — list/get plans, preview (target/operation/preconditions/effect/collateral impact per EXEC-02), approvals, and business-decision context — delegating entirely to `src/intelligence/remediation/*` rather than duplicating any business logic. This is the prerequisite the rest of Phase 3 (execution, verification) is built on top of.

Purpose: An approver cannot preview or approve execution of anything if the plan itself is unreachable over HTTP. This also fixes the deployed web UI's remediation page silently having no execution-adjacent data to show once Phase 3 features land.
Output: `src/api/routers/remediation.py`, mounted in `app.py`, with 5 read endpoints and tests.
</objective>
