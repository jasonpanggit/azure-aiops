<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| external lifecycle sources -> resolver | Public/API/vendor/AI content is untrusted candidate input. |
| resolver -> catalog repository | Only validated operator confirmation may mutate authoritative lifecycle data. |
| operator browser -> confirmation API | Candidate/date and revision inputs cross an authenticated mutation boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-09 | Tampering | catalog confirmation route | high | mitigate | Require authenticated write permission, exact normalized key, ISO date or known candidate ID, expected revision, lifecycle validation, and atomic replacement. |
| T-06-10 | Spoofing/information disclosure | candidate citations and AI provider | high | mitigate | Use HTTPS and authoritative-domain allowlists, preserve source identity/retrieval time, and send only bounded OS lookup input to the selected provider. |
| T-06-11 | Tampering | concurrent review updates | medium | mitigate | Use optimistic revision checks and return conflict without overwriting the newer catalog. |
| T-06-12 | Information disclosure | unresolved OS review UI | medium | mitigate | Apply ReadScope to candidate context and confirmation lookup; do not expose out-of-scope machine rows to candidate providers. |
</threat_model>
