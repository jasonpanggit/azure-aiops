<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Azure ARG -> ingestion | ARM/Arc payloads and provider failures enter the normalization boundary. |
| active generation -> API provider | Stored rows become scoped grouped data and evidence. |
| API -> browser | Authenticated callers receive only effective-scope DTOs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-01 | Information disclosure | `InventoryService` grouping/detail methods | high | mitigate | Apply `Scope` before grouping, pagination, evidence serialization, and every detail lookup; cover subscription and business-service isolation in API tests. |
| T-06-02 | Tampering | ARG query construction and filters | medium | mitigate | Keep fixed QuerySpec templates, validate filter bounds, and use the existing ARG client pagination/token path rather than concatenating untrusted KQL. |
| T-06-03 | Spoofing/information disclosure | provider failure handling | medium | mitigate | Preserve per-family source status and return unavailable/partial warnings; never turn an ARG exception into a successful zero-row estate. |
| T-06-04 | Information disclosure | native image metadata | medium | mitigate | Keep image fields separate from installed OS version and mark unsupported native version matches as unknown/review-required. |
</threat_model>
