<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external candidate -> review service | Candidate dates/citations are untrusted advisory input. |
| operator browser -> confirmation API | Candidate/date and revision cross an authenticated mutation boundary. |
| repository -> lifecycle DTO | Catalog data is validated before serialization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-17 | Tampering | confirmation route | high | mitigate | Require auth, exact normalized key, valid candidate/date, expected revision, lifecycle validation, and atomic write. |
| T-06-18 | Information disclosure | candidate route | high | mitigate | Apply ReadScope to candidate context and return only bounded citation/claim fields. |
| T-06-19 | Tampering | concurrent catalog updates | high | mitigate | Compare expected revision atomically and return conflict without overwriting. |
| T-06-20 | Spoofing | lifecycle source citation | medium | mitigate | Validate HTTPS and authoritative source fields before a candidate can be confirmed. |
</threat_model>
