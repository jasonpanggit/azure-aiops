## Decisions Made

- URL scope never establishes authority. Parsing begins from the current authorized scope and accepts only matching URL values, so forged or stale deep-link scope cannot broaden API requests.
- Request identity includes opaque cursor position for race rejection; retention identity excludes only cursor position and includes authorization, filters, sort, page size, and generation.
- Cursor history remains opaque and parent-owned. The codec stores/replays tokens without decoding them, and filter/scope/sort/page-size mutations clear cursor, history, page, and generation.
- Overview and facet clients omit item-only pagination and sort parameters. Target, drawer, generation, and cursor-history values remain browser context and are not sent to unsupported endpoints.
- Unknown or unproven empty responses are unavailable rather than healthy-empty. This prevents a provider failure from becoming a false zero.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Preserved exact cursor pagination typing without weakening legacy offset consumers**
- **Found during:** Task 1
- **Issue:** Replacing the shared `Pagination` interface with a cursor union would make existing offset consumers lose guaranteed `offset` and `next_offset` fields.
- **Fix:** Added a defaulted pagination generic to `Envelope`/`apiRequest` and used a dedicated `ExposureCursorPagination` only for the new methods.
- **Files modified:** `web/src/lib/types.ts`, `web/src/lib/api-client.ts`, `web/src/lib/services.ts`
- **Verification:** Full TypeScript, web tests, remediation/network regressions, and production build pass.
- **Committed in:** `3fb43967`

**2. [Rule 1 - Correctness] Separated cursor request identity from the LKG retention boundary**
- **Found during:** Task 2 review
- **Issue:** Treating an opaque next-page cursor as a new retention boundary would clear current rows during pagination, contrary to the UI contract; omitting request identity would allow late prior-page responses to win.
- **Fix:** Added distinct request and retention keys. Cursor moves retain busy rows, while scope/filter/sort/page-size/generation changes clear them and every request remains sequence-guarded.
- **Files modified:** `web/src/lib/exposure-query-state.ts`, `web/src/hooks/useExposureSection.ts`, `web/src/app/exposure/__tests__/independent-states.test.tsx`
- **Verification:** Cursor-retention, scope-clear, abort, and late-response tests pass.
- **Committed in:** `3ffbfd50`

**3. [Rule 2 - Trust Semantics] Required proof before presenting zero rows as healthy**
- **Found during:** Task 2 review
- **Issue:** A generic zero-row check could label an unknown or failed source healthy-empty and misrepresent missing evidence as no exposure.
- **Fix:** Healthy-empty now requires explicit healthy-empty or complete/current source metadata. Unknown empty responses are unavailable; partial/stale states remain explicit.
- **Files modified:** `web/src/hooks/useExposureSection.ts`, `web/src/components/exposure/SourceSectionState.tsx`, `web/src/app/exposure/__tests__/independent-states.test.tsx`
- **Verification:** Focused conservative-zero, section-state, unit, TypeScript, lint, full-suite, and build gates pass.
