# Phase 03.1 — UI Design Contract

> Visual and interaction contract for a trustworthy, accessible, independently degradable, Defender-scale Exposure experience. This refines the existing Azure AI Operations workbench; it is not a rebrand.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — preserve the repository's custom Azure AI Operations CSS and UI primitives |
| Preset | not applicable |
| Component library | Existing repository components; Fluent UI React 9 may be used where an accessible primitive such as `Dialog` is required |
| Icon library | `@fluentui/react-icons`; icons must accompany, not replace, visible text for consequential actions |
| Font | `"Segoe UI Variable", "Segoe UI", Arial, sans-serif` |

`components.json` is absent. Do not initialize shadcn or add another visual system in this phase. Reuse `PageHeader`, `EvidenceBar`, `MetricCard`, `StatePanel`, `StatusBadge`, `TableColumnFilters`, and `TablePagination`, extending their contracts rather than cloning page-local variants.

### Visual direction

- Keep the bounded 1440px workbench canvas, white operational surfaces, Azure blue interaction color, restrained radii, and existing shell.
- Use visual hierarchy to answer, in order: **Is the evidence complete? What needs attention? What can I safely do next?**
- Static cards must not lift or otherwise imply clickability. Hover elevation is reserved for links and selectable cards.
- Recommendations and available actions use brand/info treatment, not success green. Success green means observed healthy or completed successfully only.
- Overview remains a summary. Remove the full `PatchInventory` table from the Exposure landing page; full queues belong to Patch priorities.

**Sources:** existing `globals.css`, Phase 03.1 CONTEXT, Phase 10 Exposure UI review.

## Spacing Scale

Declared values are multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/text gaps, badge internals |
| sm | 8px | Compact controls, related items, dense table cells, and filter-group gaps |
| md | 16px | Default card body, section-content spacing, and metric-grid gaps |
| lg | 24px | Page sections and major card separation |
| xl | 32px | Desktop page gutters |
| 2xl | 48px | Major workflow breaks |
| 3xl | 64px | Reserved page-level separation |

Exceptions:

- Interactive targets are at least **40×40px on desktop** and **44×44px at widths below 820px**.
- Native checkbox/radio controls may render at 16×16px only when their full 44px label row is clickable.
- Dense table row height is at least 44px; do not reduce it to fit more rows.

## Typography

Exposure surfaces use exactly these four sizes and two weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / metadata | 12px | 600 | 1.4 |
| Body / table | 14px | 400 | 1.5 |
| Section heading | 18px | 600 | 1.2 |
| Page heading / numeric display | 28px | 600 | 1.2 |

- The only weights are **400** and **600**. Normalize touched Exposure rules using 500, 650, or 700.
- Table headers and compact badges are 12px, never 10–11px.
- Use tabular numerals for counts, points, dates, percentages, and score comparisons.
- Long prose uses body size and never the 28px numeric display treatment.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#eef2f7` | Workbench canvas and page background |
| Secondary (30%) | `#ffffff` | Cards, tables, navigation surfaces, dialogs |
| Accent (10%) | `#0f6cbd` | Primary CTA, active navigation indicator, text links, focus rings, selected rows, non-semantic data emphasis |
| Destructive | `#b42318` | Revoke actions, destructive confirmation, destructive failures only |

Accent is reserved for primary CTA, current navigation, links, focus, selection, and neutral chart emphasis. It must not color every card or every metric.

Existing semantic colors remain:

- Critical `#b42318`; warning/stale `#8a6100`; success/healthy `#107c10`; informational `#005a9e`.
- Every semantic color is paired with a text label and, where used, a shape/icon.
- Set Exposure normal-size muted text to `#5f6b78`; do not use `#778290` for 12–14px operational text. Text and controls must meet WCAG 2.2 AA contrast.
- Replace undefined `--danger-color` and `--border-color` references with `--color-critical` and `--color-border`.

## Information Architecture

### Shared Exposure navigation

- Render an ordinary `<nav aria-label="Exposure views">` containing links with `aria-current="page"`. Do not use `role="tab"` unless a complete ARIA tabs implementation with local tabpanels and arrow-key behavior is introduced.
- Views remain **Overview**, **Defender posture**, and **Patch priorities**.
- CVE and KB detail routes keep the originating parent selected. Default parent is Patch priorities when no valid origin is available.
- The sub-navigation scrolls horizontally at 375px without clipping labels; every link remains in sequential keyboard focus.

### Overview

1. Page header and aggregate completeness state.
2. Source coverage strip for AUM, Defender findings/posture, container images, and external enrichment.
3. Four decision metrics with explicit units and unavailable values shown as `—`.
4. Highest-value governed action, using brand/info styling.
5. Summary links to Defender posture and Patch priorities.
6. No full operational tables.

### Defender posture

1. Page header and source coverage.
2. In-page jump navigation with each section's loaded/total count and source status.
3. Scope-aggregated secure score.
4. Sections ordered: active alerts, attack paths, unhealthy recommendations, secure-score controls, container images.
5. Each section owns its data state and remains usable when peers fail.

### Patch priorities

1. Page header and source coverage.
2. SLA status with known/unknown first-detection qualification.
3. Patch and vulnerability priorities.
4. CVE exposure.
5. Risk exceptions.
6. Patch and node-image readiness, including independently loaded historical runs.

### CVE and KB detail

- Keep title, evidence, risk/impact, affected assets, and governed handoff above secondary detail.
- Attack path, external enrichment, associated CVEs, and affected findings are independent sections; failure of one does not replace the whole detail page.
- Use a three-level breadcrumb: `Exposure / {originating view} / {CVE or KB}`.

## Source-Specific State Contract

Every source-backed section implements the following state machine. A page-level spinner or error may replace the whole page only when **no usable authorized partition remains**.

| State | Visual contract | Interaction and announcement |
|-------|-----------------|------------------------------|
| Loading | Preserve section heading and controls; show 3–5 row-shaped skeletons or metric placeholders inside that section only. Existing peer sections remain visible. | Set the section `aria-busy="true"` and announce once: `Loading {source section}.` Do not repeatedly announce skeleton changes. |
| Fresh populated | Show data plus `Fresh`, observed timestamp, contributing/expected connection count, and loaded/total count. | Filters, sorting, paging, detail links, and eligible handoffs are enabled. |
| Healthy-empty | Show a neutral empty panel inside the section. Never show zero metrics as proof that other sources are healthy. | Announce `{Source} returned no {items} for this scope as of {time}.` Keep retry and source-details access available. |
| Stale last-known-good | Keep last-known-good rows and counts visible with an amber `Stale` badge and persistent callout stating data age and failed refresh. | Permit read and investigation. Disable freshness-sensitive handoffs when the server marks them ineligible; show the reason. `Retry {source}` refreshes only that section. |
| Partial / degraded | Render successful authorized partitions. Show `Partial` with `N of M connections represented`, failed source/connection names, and represented/total counts. | Controls operate only on represented rows. Bulk actions state that selection excludes unavailable partitions. Retry targets failed partitions without clearing successful rows. |
| Unavailable / error | Show an inline error panel for that section with source identity, safe error summary, last attempt, and retry. Do not render `0`. | `Retry {source}` retains focus and reports progress. Other sections remain operable. |

### Required independent sections

| Route / surface | Independently stateful sections |
|-----------------|--------------------------------|
| Overview | summary, patch priority preview, asset counts, Defender overview, SLA, risk exceptions |
| Defender posture | overview, alerts, attack paths, secure score, controls, recommendations, container images |
| Patch priorities | priorities, SLA, CVE exposures, risk exceptions, patch targets, historical runs |
| CVE detail | scoped detail/findings, attack path, NVD/CVSS, EPSS, KEV, KB mapping |
| KB detail | scoped KB metadata, MSRC CVE associations, affected findings |

Additional rules:

- A failed refresh with last-known-good data is **stale/degraded**, not unavailable and never healthy-empty.
- A true successful zero-row response is **healthy-empty** only when source status, scope, and successful checkpoint prove it.
- Unknown or unavailable metrics render `—` with explanatory detail; never coerce missing data to `0`.
- Header wording and the `PageHeader` signal must reflect `Complete`, `Partial`, `Stale`, or `Unavailable`. Remove the unconditional green pulse and “Live operational context” label when the state is not fresh and complete.
- `EvidenceBar` summarizes aggregate state conservatively, then exposes source/connection details in a disclosure. The freshest source must not mask a stale peer.

## Score and Unit Contract

| Value | Display contract |
|-------|------------------|
| Defender secure score | API ratio `0..1` becomes percentage by `ratio × 100`. Across subscriptions display `sum(currentScore) / sum(maxScore) × 100`, rounded to one decimal. Label `Secure score — all authorized subscriptions`; detail `{current} of {max} points across {N} subscriptions`. Never display only the first subscription. |
| Secure-score control | Show `{currentScore} / {maxScore} points` and the derived percentage to one decimal. A ratio of `0.25` displays `25.0%`, not `0%` or `0.25%`. |
| SLA compliance | Ratio becomes percent by `ratio × 100`, rounded to one decimal; detail states compliant and tracked counts. Unknown first detection is `SLA age unknown`, not overdue or zero days. |
| CVSS | Show one decimal followed by `/10`, for example `8.8/10`. |
| EPSS | Probability ratio becomes a percent with one decimal. Percentile is separately labeled, for example `92nd percentile`. |
| Composite exploit risk | Show `{score}/100` and retain its CVSS/EPSS/KEV explanation. Do not label it as a probability. |
| Expected risk reduction | Show `Risk reduction score {score}/100`; do not append `%` unless the API explicitly returns a percentage unit. |
| Counts | Whole numbers with locale separators. Every collection distinguishes `loaded`, `represented`, and `total`. |

Success color is prohibited for “highest-value patch” or a high score unless the value itself is a verified successful/healthy state.

## Server Pagination, Filtering, and Total Counts

- All Exposure collections use deterministic server-side filtering, sorting, and opaque cursor pagination over the governed persisted read model.
- The TypeScript response preserves `returned_count`, exact `total_count`, `next_cursor`, `has_more`, source completeness, represented connection count, expected connection count, and freshness.
- Default page size is **50**; choices are **25, 50, 100**. Changing page size, scope, query, filter, or sort clears the cursor and returns to page one.
- The footer copy is `Showing {first}–{last} of {total} {noun}` and additionally exposes `{returned_count} loaded` when loaded differs from represented or total.
- Previous/next controls use the server continuation contract. Do not infer completeness from `data.length`, and do not slice a fully fetched array in the browser.
- Search is server-owned, visibly labeled `Search exposure`, and debounced by 300ms. Enter submits immediately.
- Sortable headers are buttons with visible direction and `aria-sort`; the default sort is operational priority descending with a stable unique-ID tie-breaker.
- Preserve filters and sort in the URL. Cursor state may be in the URL only if it is opaque and safe to replay.
- While moving between pages, retain the current rows, mark the table busy, disable duplicate navigation, and replace rows only after the requested page succeeds. On failure, retain current rows and show an inline retry.
- Selection is current-page only by default. “Select all” must say `Select all {N} exceptions on this page`; never imply selection of unloaded rows.
- At 100,000 findings, the default first page and each filter/sort request must meet a configurable default **p95 ≤ 2 seconds** authenticated SLO. Skeletons appear without layout shift while waiting.

## Responsive Dense Tables

| Viewport | Contract |
|----------|----------|
| 1440×900 | Full dense table. Use sticky header, stable column widths, 14px body, 12px header, and a sticky identity column only when it does not cover focused content. |
| 768×1024 | Keep priority columns visible; place the table in a labeled horizontal-scroll region with `min-width: 960px` for 6–8 columns. Show a one-time `Scroll horizontally to see all columns` hint. |
| 375×812 | Convert 6–8 column tables to stacked row cards/definition lists. Show identity, severity/status, top impact, source state, and primary action first; remaining fields expand under `Show details`. Do not force the page itself to scroll horizontally. |

- Tables with five or fewer short columns may remain tables on mobile if they fit without shrinking text.
- Each table has a caption, correct header associations, and an accessible scroll-region label.
- A row is not a single click target. Use explicit links/buttons so keyboard and assistive-technology users can distinguish open, select, expand, resource, and remediation actions.
- Long ARM IDs, digests, CVSS vectors, error messages, and remediation text wrap with `overflow-wrap:anywhere` in details. In dense rows, clamp to two visual lines with the full value available to assistive technology and through `Show details`/copy.
- Footer controls wrap below the range at narrow widths and meet 44px touch targets.
- Keep focused elements visible when a sticky header/column is present.

## Accessibility Contract

- Meet WCAG 2.2 AA for contrast, keyboard access, focus visibility, names/roles/values, status announcements, and 200% zoom.
- Every search input has a persistent `<label>`. Every select-all and row checkbox has an accessible name including the affected CVE/server or page count.
- Use native buttons and links. Expanders expose `aria-expanded` and `aria-controls`.
- Source loading uses polite status announcements; source failure and mutation failure use `role="alert"`. Do not move focus for background refreshes.
- After a submitted form error, focus the error summary; associate field errors using `aria-describedby`. After success, announce the audit identifier and move focus to the success summary.
- All status meaning is conveyed by text, not color alone.
- Expose full dates to assistive technology while visible copy may use relative time. Include timezone for exact timestamps.
- Apply `prefers-reduced-motion: reduce` to all Exposure animation, including cards, critical metrics, skeletons, charts, and header pulses.
- Charts require a text summary/table of the same values. No decision fact may exist only in a chart.
- At 200% zoom and 320 CSS pixels, content reflows without loss of actions or two-dimensional page scrolling.
- Test sequential focus across navigation, filters, pagination, row actions, dialogs, and return navigation.

## Risk-Exception Safety and Feedback

### Record risk exception

- Label the action `Record risk exception`, not `Accept risk`, to emphasize an auditable record rather than removal.
- Confirmation dialog shows exact CVE, affected target scope, what metrics will exclude, current evidence freshness, and optional expiry.
- Reason is required. Approver identity is read-only from the authenticated session; do not accept a free-text `Approved by` identity.
- Primary confirmation is `Record exception`; secondary is `Keep reviewing`.
- While submitting, disable duplicate submission and retain entered values.
- On success, show `Risk exception recorded` with audit ID, effective scope, expiry, and `Revoke risk exception` only if the server exposes a governed revocation transition.
- If recording succeeds but refresh fails, state `Exception recorded; updated exposure counts could not be refreshed` and preserve the audit result.

### Revoke risk exceptions

- Use `.button-danger` backed by `--color-critical`; never undefined inline variables.
- Single and bulk revoke require a destructive dialog. Bulk copy names the count and clarifies that exposure metrics may increase.
- Default bulk selection is the current page only. The dialog lists selected identities and represented source scope.
- If any item fails, stop scheduling unattempted client-side requests. Report **succeeded, failed, and not attempted** counts and per-item outcomes.
- Successful rows are deselected and refreshed. Failed and not-attempted rows remain selected for retry.
- Announce progress and final outcome in an `aria-live="polite"` region; final failure summary uses `role="alert"`.
- Never log the only error to the console, clear a failed selection, or silently continue.

## Navigation and Context Continuity

- Collection-to-detail links preserve an allowlisted internal origin, scope, search, filters, sort, page size, and scroll anchor.
- Return context must not permit open redirects. Accept only canonical Exposure paths and validated query keys.
- Detail breadcrumbs and a visible `Back to {originating view}` action restore filters and the previous row position after data loads.
- Direct-linked CVE/KB routes default to Patch priorities context and remain valid without browser history.
- CVE-to-KB and KB-to-CVE links carry the same origin context rather than resetting to Overview.
- Scope remains the global authorized scope; URL state may describe it but never widen it.
- Details show the originating parent as active in Exposure navigation.
- External Azure/Defender resource links state that they open Azure portal, open in a new tab, and include `rel="noopener noreferrer"`.

## Governed Remediation Handoffs

- The primary Exposure CTA is **`Open governed remediation`**. Replace ambiguous `Remediate` and `Create patch plan` labels.
- Handoffs are available from eligible patch priorities, CVE/KB details, Defender recommendations, alerts/attack paths with guidance, and container-image findings.
- A handoff carries identifiers and review context only: canonical target ID/type, CVE/KB/image digest, authorized scope, originating route/filter state, evidence generation/snapshot ID, and source completeness.
- The server re-derives executable targets and owns eligibility. Browser query parameters never authorize, approve, or widen an action.
- Before navigation, show concise context: `You will review {N} targets and {N} updates in governed remediation. Nothing executes from Exposure.`
- If evidence is stale, partial, or unavailable, show the server-projected eligibility. Disable only when the server says no safe handoff is available, with a visible reason and next step.
- The remediation workspace displays `From Exposure` context and provides `Back to exposure` with the original state.
- Handoff creation failure leaves the user on Exposure, retains selection/context, and offers `Retry handoff`.
- Partial correlation is explicit: `Handoff created for {N} of {M} represented targets`; list excluded targets and reasons.
- Do not add remediation action types or autonomous execution in this phase.

### Defender and container action matrix

| Finding surface | Governed handoff | Resource / evidence deep link |
|-----------------|-------------------|-------------------------------|
| Defender alert | `Open governed remediation` when the server projects eligible target(s); partial scope lists excluded targets/reasons | `Open affected resource in Azure portal`; when supplied by the governed API, `Open alert in Defender for Cloud` |
| Defender attack path | `Open governed remediation` for the server-projected remediable path nodes; represented/total and excluded nodes remain visible | `Open attack path in Defender for Cloud` and per-node `Open affected resource in Azure portal` |
| Defender recommendation | `Open governed remediation` for eligible represented resources | `Open recommendation in Defender for Cloud` plus `Open affected resource in Azure portal` |
| Container-image finding | `Open governed remediation` opens an audited review handoff for the digest/represented targets, or the server returns no safe action. It never creates or invokes a rebuild, base-image, workload-mutation, or deployment action. | `Open registry in Azure portal`; when observed workload evidence exists, `Open cluster in Azure portal`; unknown workload produces no inferred link |

All external links are constructed or validated by one governed portal-link helper.
Allow only HTTPS links on `portal.azure.com` (including documented Defender blades)
or canonical ARM-resource links generated from authorized IDs. Open in a new tab,
announce that behavior, and set `rel="noopener noreferrer"`. Reject or omit
`javascript:`, non-HTTPS, user-supplied hosts, malformed encodings, and out-of-scope
resource IDs. A missing/unsafe portal link must not suppress the governed handoff.
Focused component tests cover each row above, safe-link rejection, stale/partial/
unavailable eligibility, partial results, excluded reasons, retry, and preserved
origin/filter context.

The container handoff is review-only. Phase 03.1 must not add executable
container action IDs, execution adapters, or automatic build/deployment calls;
focused tests pin the existing execution registry and prove zero container
operation invocations.
