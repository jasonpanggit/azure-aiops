## Decisions Made

- A failed durable record remains usable when it has an LKG payload, but its failed status, safe error code, original success/source/enrichment timestamps, and stale flag remain visible.
- All-due selection filters by `refresh_after` before applying `max-items`, preventing fresh items from starving due work.
- API construction opens a fresh durable-cache facade so separately committed job records become visible without a process restart; it does not resolve any external enrichment provider.
- The scheduled job is an additive sibling resource. The existing API resource's manifest-derived specialist variables, promotion gate, version pinning, and rollback selection remain byte-for-byte unchanged.
- Environment CVE routes no longer perform unrestricted public-catalog fallback. Durable enrichment augments identifiers already present in authorized findings; it never establishes tenant membership.
