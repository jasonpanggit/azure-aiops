## Decisions Made

- Failure and success are different Python types. `AcquisitionFailure` deliberately
  has no `rows` member; only `AcquisitionSuccess` may cross the normalization boundary.
- A successful empty result is not inferred from `[]`; it requires a
  `PagingProof(complete=True)` produced only after ARG continuation exhaustion.
- Existing low-level `query()` callers remain compatible, while authoritative
  acquisition uses `query_with_metadata()` so the change is additive.
- Existing ingestion paths reject a mixed typed batch before normalization. Plan
  03.1-07 can later add per-partition LKG publication without allowing a failed
  source to false-clear current data.
