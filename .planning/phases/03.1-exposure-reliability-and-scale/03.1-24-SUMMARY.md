## Decisions Made

- A header without aggregate evidence metadata stays visually neutral instead of preserving the previous unconditional “Live operational context” claim. Existing call sites remain type-compatible through the optional prop.
- Completeness state outranks individual contributor freshness. Complete evidence must additionally be current before the live signal is permitted.
- Cursor tokens are not a pagination prop and never reach rendered markup. The parent supplies only exact server facts and validated history availability.
- Exposure cursor page-size options are separate from existing client/offset options, preserving legacy behavior while enforcing 25/50/100 and default 50 for the new mode.
- The dialog accepts full existing remediation governance types rather than defining a reduced local projection. Mutation transport remains caller-owned.
- A selected revoke item missing from the server result is conservatively synthesized as `not_attempted`; only explicit success clears selection.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Retained selected revocations with omitted server outcomes**
- **Found during:** Overall verification and conservative-result review after Task 3
- **Issue:** A malformed or incomplete per-item revoke response could omit a selected exception. Treating only returned failures as retryable would silently clear the omitted item even though no success was proven.
- **Fix:** Normalize results against the page-bounded selection, synthesize omitted items as `not_attempted`, display the omission reason, and retain every non-success item for retry.
- **Files modified:** `web/src/components/exposure/RiskExceptionDialog.tsx`, `web/src/components/exposure/RiskExceptionDialog.test.tsx`
- **Verification:** Focused dialog tests, full 47-file web suite, TypeScript, lint, and production build pass.
