# Phase 03.1: Exposure Reliability and Scale - Context

**Gathered:** 2026-09-03
**Status:** Ready for planning
**Source:** PRD Express Path (`.planning/phases/10-fabric-medallion-capability-expansion/10-EXPOSURE-DEEP-REVIEW.md`)

<domain>
## Phase Boundary

This phase makes the Exposure capability authoritative, failure-tolerant,
temporally correct, ontology-complete for container images, and usable at
Defender-scale volumes before Phase 4 pilot validation.

It covers the complete Exposure path from ARG/AUM and Defender acquisition,
through normalized Bronze/Silver/Gold products and ontology relationships, to
scope-enforced API contracts, web decision support, remediation correlation,
and Copilot tools.

It does not broaden remediation execution beyond the existing approved,
bounded action contracts. It does not implement unrelated Phase 4 incident,
change-correlation, or operational-twin pilot scenarios.

</domain>

<decisions>
## Implementation Decisions

### Unified scoped Exposure truth

- One governed, scope-aware read model is authoritative for summaries,
  exposure lists, Defender posture, container images, CVE/KB details, SLA,
  remediation, web, and Copilot.
- Live AUM observations overlay the persisted scoped snapshot; they must not
  replace or hide Defender-only or image evidence.
- AUM and Defender remain separately attributable source families even when a
  canonical target/CVE observation is merged.
- Scoped CVE and KB environment membership is derived only from identifiers
  visible in the caller's authorized findings. External catalog lookup must
  use a separate contract that does not reveal cross-scope membership.
- Live and persisted AUM normalization share one contract, including
  list-shaped classifications and `msrcSeverity`.

### Source checkpoints, quality, and freshness

- Each connection/source family has an independently checkpointed
  last-known-good partition.
- Acquisition failures never become domain entities and never false-clear the
  prior successful partition.
- API evidence distinguishes complete, partial, stale, unavailable, and
  healthy-empty states and reports contributing source/connection coverage.
- Event time, first detection, last observation, ingestion time, run time,
  publication time, and enrichment time remain separate fields.
- Multi-connection reads isolate failures and return successful authorized
  partitions with explicit partial-result metadata unless no usable partition
  remains.
- External CVE/KB/EPSS/KEV enrichment is materialized asynchronously with
  durable per-item success, failure, source timestamp, and stale status.

### Temporal exposure state

- Missing, installed, resolved, and reintroduced observations are immutable.
- Current state is derived from canonical target plus CVE/KB identity, event
  time, successful operation status, and generation order.
- An installation closes a missing state only when its successful completion
  is later than the relevant missing observation.
- SLA age starts at tenant-scoped first detection, never patch publication.
  Unknown first detection remains unknown rather than being fabricated.
- Exposure history supports deterministic replay for the evidence snapshot
  used by a recommendation.

### Container-image ontology

- Container images and immutable digests are stable ontology entities rather
  than only aggregate API rows.
- The graph represents CVE observation, registry/repository ownership,
  deployed workload, application, business service, and remediation ownership
  relationships without treating registries as servers.
- Image relationships survive normalization, Fabric persistence, ontology
  rebuild, and graph publication.
- Container findings participate in prioritization and downstream impact only
  through type-aware logic that preserves server/image distinctions.
- For container findings, remediation correlation ends at an audited governed
  review handoff or an explicit no-safe-action result. This phase adds no
  executable container rebuild, base-image, workload-mutation, or deployment
  action type/adapter, and Exposure never invokes those operations.

### Scalable API and operator experience

- Exposure collections support deterministic server-side filtering, sorting,
  and cursor pagination over a persisted governed read model.
- API and TypeScript contracts preserve returned count, total count,
  continuation state, source completeness, and freshness.
- Web pages show loaded/total counts and independent loading, error, empty,
  stale, and degraded states per source section.
- Defender secure-score values use explicit units and correct ratio-to-percent
  conversion and aggregation/labeling across subscription scope.
- Risk-exception and remediation handoffs are accessible, confirmed,
  auditable, and visibly report partial success/failure.
- Exposure detail routes preserve the originating view/filter context and
  provide governed remediation/resource deep links.
- Dense tables support keyboard use, accessible labels, readable contrast,
  deliberate responsive layouts, and touch targets appropriate for mobile.

### Verification and observability

- Cross-layer reconciliation tests prove that AUM-only, Defender-only, shared,
  and image findings produce consistent scoped counts across Silver/Gold,
  ontology, API, web, remediation, and Copilot.
- Failure-injection tests prove last-known-good retention and partial-source
  behavior for each source family and multi-connection reads.
- Temporal tests cover missing-to-installed, installed-to-missing,
  reintroduction, stale installation, out-of-order events, and unknown first
  detection.
- Scale tests prove complete, duplicate-free pagination at 100,000 findings
  within an agreed first-page SLO.
- Telemetry reports per-source checkpoints, row-count drops, merge outcomes,
  enrichment quality, API represented/total counts, and cross-layer
  reconciliation drift.
- Authenticated UI validation covers real Defender volumes, keyboard and
  screen-reader behavior, and 375x812, 768x1024, and 1440x900 layouts.

### the agent's Discretion

- Exact Gold table names, cursor encoding, and internal repository/query
  abstractions.
- Whether temporal state is implemented as event sourcing or an append-only
  observation table plus deterministic materialized current-state projection.
- Exact freshness thresholds and first-page latency SLO, provided they are
  configurable and verified.
- Visual composition of the Exposure landing page, provided the decision
  hierarchy and independent source states remain clear.
- Rollout flags and migration sequencing, provided old and new read models can
  be reconciled before cutover and rollback is explicit.

</decisions>

<specifics>
## Specific Ideas

- Lead with a production-quality tracer containing one AUM-only finding, one
  Defender-only finding, one merged target/CVE finding, and one vulnerable
  deployed image. Prove the same scoped result across API, web, ontology,
  remediation, and Copilot before expanding.
- Treat source completeness as user-visible evidence, not only ingestion
  telemetry.
- Prefer a persisted Gold Exposure read model over rebuilding large exposure
  collections during API service construction.
- Use shadow reconciliation before switching aggregate routes to the unified
  read model.

</specifics>
