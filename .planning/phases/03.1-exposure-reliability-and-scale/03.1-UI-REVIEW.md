# Phase 03.1 — UI Review

**Audited:** 2026-09-18
**Baseline:** `.planning/phases/03.1-exposure-reliability-and-scale/03.1-UI-SPEC.md`, Phase 03.1 context/summaries, and current `twin` source
**Scope:** `web/src/app/twin/page.tsx` and its related rules in `web/src/app/globals.css`
**Screenshots:** Not captured. No local server responded on ports 3000, 5173, or 8080, and the supplied live URL returned HTTP 200 but browser automation was unavailable because Playwright Chromium is not installed. The attached/available screenshots show Exposure pages, not the operational twin, so they were not treated as visual evidence for this page. Live rendering, authentication state, data density, and responsive behavior remain unverified.

> This is an adversarial source audit, not a claim that the live page was visually inspected. Phase 03.1's context also says the phase does not implement unrelated operational-twin pilot scenarios; this page is therefore assessed for consistency with the shared operational visual contract and for implementation quality, not credited as a Phase 03.1 Exposure surface.

## Top 3 Priority Fixes

1. **Make all request states independently explicit and preserve unknown values** — Users can read a fabricated `0` risk/risk delta/impacted count while scenario, traversal, comparison, or export requests are still pending or failed. Add per-section loading/error/empty state with retry, keep `null`/`—` for unobserved metrics, and surface the failure reason rather than silently ignoring rejected promises (`page.tsx:81-95, 211-220, 268-299`).
2. **Normalize the page to the approved typography and spacing tokens** — The current page inherits 650/700 weights, 10/11/13/15px text, a 30–40px heading, and non-scale gaps/padding. Replace touched values with 12/14/18/28px, 400/600, and 4px multiples; make controls at least 44px below 820px (`globals.css:827-837, 2992-3029, 3031-3054, 2165-2204`).
3. **Re-establish a decision-first composition** — The page currently gives equal card weight to risk, model internals, temporal history, scenario analysis, dependency evolution, Copilot prompts, and raw JSON. Lead with evidence/freshness, risk/impact, and the safe next action; progressively disclose raw export and technical context, and replace pill-cloud presentation with a compact accessible summary/table (`page.tsx:211-345`).

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**WARNING — generally specific but overloaded.**

- Good operational language is present: “Refresh current state”, “Copy export”, “Twin unavailable”, “Loading twin”, “Business impact traversal”, “Dependency evolution”, and “Raw twin export” (`page.tsx:178-200, 242-343`). These are materially better than generic “Submit” or “Save” labels.
- The fallback “No resource traversal is available for the current scope” is scoped and useful (`page.tsx:261`).
- “Select a scenario to estimate impact.” is misleading when the selected scenario request has failed or is still pending; there is no separate loading/error copy for that action (`page.tsx:288-299`).
- “Current twin risk signal” and the default `0` risk imply an observed value before the snapshot exists (`page.tsx:37-45, 211-220`). Use “Unavailable until current evidence loads” and an em dash instead of a numeric zero.
- “Copy export” has no success/failure feedback, so the user cannot tell whether clipboard access succeeded (`page.tsx:186-193`). Use a stateful label/announcement such as “Export copied” or “Copy failed—download JSON”.

### Pillar 2: Visuals (2/4)

**WARNING — hierarchy is structurally present but not decision-oriented.**

- The header establishes a title, description, and action group (`page.tsx:174-209`), and the source uses shared `PageHeader`, `EvidenceBar`, `MetricCard`, `StatePanel`, and `StatusBadge` primitives as requested by the design contract.
- The first content block combines a decorative-looking `RiskGauge` with three metrics (`page.tsx:211-225`). The contract says charts must clarify evidence and be paired with equivalent text; the source does not show a textual risk interpretation, scale, threshold, or confidence adjacent to the score.
- Six more equal-weight cards follow before raw JSON: twin model, traversal, temporal view, scenario analysis, dependency evolution, and Copilot grounding (`page.tsx:227-333`). This makes “what needs attention” and “what can I safely do next” compete with implementation/audit detail.
- Entity counts are rendered as nine rounded pills (`page.tsx:231-239`; `globals.css:2137-2163`). This is visually dense and does not expose entity semantics or an ordered table for users who need to scan counts.
- The available screenshot evidence is for an Exposure page only and is not evidence for this route. No live visual claim is made.

### Pillar 3: Color (2/4)

**WARNING — token foundation is good, but touched rules do not consistently follow the contract.**

- The dominant canvas/surface/brand variables are correctly declared (`globals.css:1-28`) and the page uses shared cards and badges rather than page-local hardcoded colors.
- The contract requires normal-size muted operational text to use `#5f6b78`; the shared `--color-text-muted` remains `#778290` (`globals.css:10`). Twin-specific metadata uses that muted token through `.risk-gauge-label`, `.risk-gauge-detail`, `.timeline-list small`, and `.compact-row small` (`globals.css:2165-2183, 3014-3029`), so the stated contrast/token requirement is not met.
- Touched rules use hardcoded `#ffffff` and `#0f6cbd` in nearby global styles (`globals.css:835-837`, `globals.css:839-847`, `globals.css:871`), making the visual system less auditable and increasing the chance of accent/white misuse. Prefer `var(--color-surface)` and `var(--color-brand)` where the value is semantic.
- The gauge's semantic color mapping is not visible in the audited source; because the current risk fallback is zero, an unavailable state may look healthy. Unknown and healthy must have visibly distinct, labeled treatments.

### Pillar 4: Typography (1/4)

**BLOCKER — direct contract mismatch across shared rules used by this page.**

- UI-SPEC requires exactly 12/14/18/28px and only 400/600 for Exposure surfaces. The page's heading rule is `clamp(30px, 3vw, 40px)` (`globals.css:827-837`), and `h1`/`h2` use `font-weight: 650` (`globals.css` around the base heading rules), directly violating both size and weight requirements.
- The risk gauge uses `font-size: 28px; font-weight: 700` and detail text at 11px (`globals.css:3014-3029`). The page also uses 10px eyebrow, 12px labels, and 13px/15px styles elsewhere in the shared sheet. These are not the declared two-weight/four-size scale.
- The twin source adds `font-weight: 650` through `.panel-lead` and `.field-label` (`globals.css:2185-2194`) and relies on those rules in scenario/traversal/temporal sections (`page.tsx:247, 270, 294`).
- Numeric values are not explicitly tabular in the twin-specific rules, despite the contract requiring tabular numerals for counts and risk comparisons.

### Pillar 5: Spacing (2/4)

**WARNING — coherent layout, but not on the declared scale.**

- The grid structure is understandable: 18px page stack gap, 16px two-column grid gap, 8px pill gap, and 12px summary gap (`globals.css:2115-2145, 3031-3054`). Most of these are near the contract but 18px and 12px are not declared scale tokens.
- Twin-specific rows use 9px gaps and 10px/12px padding (`globals.css:2165-2183`); header/summary uses 22px bottom margin (`globals.css:823-825, 3031-3037`). Normalize these to 4/8/16/24/32px where the density allows.
- The select is only `min-height: 38px` (`globals.css:2196-2204`), and the page's buttons inherit shared minimums not demonstrated here. The contract requires 40px desktop and 44px below 820px; this is an interaction and spacing risk on mobile.
- The mobile breakpoint changes `.page-header` to a column but does not add a twin-specific rule making the three header actions one-per-row or guaranteeing 44px controls (`globals.css:5675-5690`). This is unverified without a live mobile capture.

### Pillar 6: Experience Design (2/4)

**WARNING — baseline graph state coverage exists, but the composed experience is not failure tolerant.**

- The initial graph/compare request uses `Promise.allSettled`, but only the graph rejection is surfaced; comparison failure is silently ignored (`page.tsx:65-79`). The dependent scenario/traversal/export request also uses `Promise.allSettled` and silently ignores every rejection (`page.tsx:81-95`).
- The Refresh button only calls `twinApi.graph(scope)` and does not refresh comparison, scenario, traversal, or export, nor set loading/error state (`page.tsx:182`). This can leave a mixed-revision page after refresh.
- `scenarioType` changes trigger a request, but there is no scenario-local pending, retry, or error state. The UI retains the previous result or falls back to “Select a scenario…” without indicating which condition applies (`page.tsx:278-299`).
- The initial loading/error panels are useful (`page.tsx:199-200`), but the rest of the page still renders default metric values while `snapshot` is absent (`page.tsx:217, 219-220, 296-298`). This conflates not-yet-loaded with a measured zero.
- Copying export has no disabled state, progress state, or announcement (`page.tsx:186-193`), and there is no visible confirmation for the clipboard operation.
- The page has no destructive action, so a destructive confirmation is not applicable. Copilot is opened through a labeled control (`page.tsx:181`), which is a positive accessibility detail.
