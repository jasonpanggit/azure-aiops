## Pattern Assignments

### 1. Immutable observations and deterministic current-state projection

**Apply to:** `models.py`, new `exposure_contracts.py`, new `exposure_projection.py`, `dataset_mapper.py`, `vulnerability_pipeline.py`, `runtime.py`.

**Reuse:** the repository's explicit history/current write-mode split. `src/storage/delta_writer.py:17-26`:

```python
class DeltaWriteMode(StrEnum):
    OVERWRITE = "overwrite"
    APPEND = "append"
    MERGE = "merge"
    SNAPSHOT_MERGE = "snapshot_merge"
```

For immutable observation identity, use `APPEND`, which rejects mutation of an existing key (`src/storage/delta_writer.py:149-176`):

```python
if previous is not None and _canonical_row(previous) != _canonical_row(row):
    raise ValueError(f"Append row mutation for key {key}")
```

Use `MERGE`/`SNAPSHOT_MERGE` only for the derived current projection. The existing dispatch is at `src/fabric/sync_service.py:1609-1616`; its test is `tests/test_incremental_sync.py:1009-1031`.

**Extend:** `VulnerabilityFinding` (`src/intelligence/vulnerability/models.py:181-226`) with separate event, detection, ingestion, run, publication, and enrichment times. Do not overload `first_observed_at`.

**Avoid:** the current membership-only close and publication-time SLA assignment:

- `src/api/runtime.py:809-835` builds an undated `installed_kbs` set and assigns `published_at` to `first_observed_at`.
- `src/api/runtime.py:929-935` suppresses every matching missing row regardless of event order.

The current `silver_patch_history` schema (`src/fabric/schema_registry.py:191-200`) is a useful history-table precedent but is not sufficiently granular to be the new observation contract.

**Test analogs:** extend `tests/test_vulnerability_intelligence.py:165-209` (including the existing “unknown first observation means no SLA” behavior) with the full missing → installed → missing/reintroduced, stale install, failed install, out-of-order, replay, and unknown-first-detection matrix.

### 4. Opaque server cursor and completeness-aware API envelope

**Apply to:** `api/dependencies.py`, `api/evidence.py`, vulnerability router,
Exposure read port, `web/src/lib/types.ts`, `services.ts`, and
`TablePagination.tsx`.

**Extend:** the common envelope rather than introducing a route-local wrapper.
`src/api/evidence.py:125-179` already centralizes `data`, evidence, scope,
knowledge version, warnings, and pagination.

The new Exposure page metadata must preserve:
`returned_count`, exact `total_count`, `next_cursor`, `has_more`,
represented/expected connection counts, source completeness, and freshness.

**Partial analog for continuation control flow:** `FabricClient.iter_items`
(`src/fabric/fabric_client.py:79-113`) advances an opaque continuation and avoids
silently re-fetching the same page:

```python
if continuation_uri:
    next_path = str(continuation_uri)
    query = None
elif token:
    next_path = base_path
    query = {"continuationToken": token}
else:
    return
```

Do not accept arbitrary continuation URLs for the Exposure cursor. Cursor payloads
must be server-issued, versioned, integrity-protected, bound to effective scope +
filter + sort + page size, and decode to the stable sort tuple.

**Avoid:** the current vulnerability-router collection path that builds the full
collection, filters in Python, and slices by offset. Extend
`web/src/lib/services.ts::vulnerabilityApi` in place rather than replacing the
shared service module or its neighboring `remediationApi` and `networkApi`
exports.

**Extend UI:** `TablePagination` already exposes server totals and accessible
previous/next controls (`web/src/components/ui/TablePagination.tsx:46-145`), but
replace page-number arithmetic with an opaque cursor history stack. Preserve rows
while the next page is pending.

**Test analogs:**

- `tests/test_fabric_client.py:79-161,287-305` — continuation advancement and unsafe-origin rejection.
- `tests/test_api_inventory_router.py:100-113` — scope, page metadata, and partial source state in one response.

## Shared Patterns

### Authorization and scope

**Source:** `src/api/dependencies.py::{ApprovePrincipal,OperatePrincipal}`,
`src/api/routers/operations.py::{read_remediation_decisions,record_remediation_decision}`,
and `src/api/routers/remediation.py::{_authorize_execution_scope,plan_workflow,execute_plan,retry_execution,supersede_execution,cancel_execution}`.  
Apply `ReadScope` before querying. Preserve the existing single decision POST
route in `operations.py` with `ApprovePrincipal`; do not duplicate it in the
remediation router. Preserve `OperatePrincipal` for execution, retry, cancel,
supersede, and diagnostics. Execution reads authorize from the durable record's
immutable scope attributes even if the originating plan disappears. Cursor
decoding and external catalog lookup must never widen effective scope.
Environment CVE/KB membership is derived from visible findings; unrestricted
feed lookup is a separate external-catalog contract.

### Post-Phase-03.2–03.6 remediation preservation

**Runtime source:** `src/api/runtime.py::_hybrid_remediation_cache`,
`::hybrid_remediation`, `::_remediation_decision_store`,
`::_remediation_execution_store`, `::_build_vulnerability_service`,
`::_target_evidence_refresher`, and `::_verification_coordinator`.

- Runtime edits are additive around the TTL-cached planner/repository view and
  module-shared decision/execution stores.
- Preserve `observed_asset_ids=observed_target_ids`; reconciliation must
  distinguish an observed clean target from an absent/wrong-scope target.
- Preserve the target evidence refresher's cached `hybrid_vulnerability` path.
- Preserve coordinator construction with `plan_repository=None` and
  `patching_service=None`; it may poll and reconcile durable records but may not
  execute, retry, or supersede plans.

**Schema source:** the `silver_remediation_approval_policies` registry entry in
`src/fabric/schema_registry.py` and its parser in `src/fabric/sync_service.py`.
Every Phase 03.1 schema/sync edit must retain nullable `role_ids_json` and map it
to policy `role_ids`.

**Frontend source:** `web/src/lib/types.ts::RemediationDecision`,
`web/src/lib/services.ts::{RemediationApprovalRequirement,RemediationExecution,RemediationWorkflow}`,
and `web/src/app/remediation/page.tsx`. Shared edits must retain
`approver_roles`, `approval_policy_version`, `approval_role_id`,
`admin_override`, `self_approved`, `self_approval_policy_id`, requirement
`role_id`, `provider_submitted`, `failure_class`, `submitted_attempt_count`,
supersession lineage, verification scheduling, blockers/degradation, and
evidence reconciliation. Preserve `can_operate`, nullable fail-safe patch
selection, bounded polling, recovery controls, reconciliation, and lineage.

### Validation before publication

**Source:** `src/intelligence/inventory/fabric_publication.py:34-51`  
Validate every contract before changing the active generation. A failed required
partition keeps its previous checkpoint and records degradation; it does not
activate a false-clear partition.

### Conservative completeness

**Source:** `src/api/evidence.py:136-153` and
`src/fabric/schema_registry.py:490-512`  
Return source/connection status in the common envelope. Aggregate freshness is the
least trustworthy required contributor, never the newest timestamp.

### Stable identity and deterministic ordering

Use canonical target ID + target type + CVE/KB/image digest + event identity for
observations. Cursor order requires a unique stable tie-breaker. Relationship IDs
continue to use the canonical ontology builder, not page-local hashes.

## Dependency Ordering

1. **Contract tracer first:** AUM-only, Defender-only, merged, and image fixture;
   temporal observation/current-state models; Silver/Gold/enrichment/status
   contracts; acceptance reconciliation assertions.
2. **Acquisition safety:** reject failure rows, per-source/per-connection
   checkpoints, carry-forward, explicit generation completeness.
3. **Persistence and projection:** immutable observations, deterministic current
   projection, durable enrichments, Gold query indexes.
4. **Ontology round-trip:** image/digest entities and relationships through mapper,
   Delta, rebuild, validator, and graph traversal.
5. **Read port and API:** unified scoped provider, server filter/sort/cursor,
   envelope completeness, scoped CVE/KB membership.
6. **Consumers:** TypeScript envelopes/services, shared source-state/table
   components, then Overview/Defender/Patch/CVE/KB pages and governed handoffs.
7. **Rollout gates:** flags → shadow reconciliation → telemetry baseline → 100k
   benchmark → authenticated live validation → cutover; rollback remains tested.

Do not start web cutover before the Gold read-port envelope is stable. Do not
activate the new serving flag before temporal, scope, pagination, source-failure,
and ontology round-trip gates are green.
