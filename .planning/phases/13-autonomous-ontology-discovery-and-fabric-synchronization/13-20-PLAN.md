## Trust Boundaries

| Boundary | Description |
|---|---|
| Live validator → deployed API/Jobs/Fabric | Credentialed reads and bounded actions cross production-like service boundaries. |
| Deployed artifacts → retained report | Raw cloud identifiers and errors must not leak into evidence. |
| Report provenance → verifier | Local evidence must not masquerade as deployed behavior. |
| Fixture principal → Azure test subscription | The drill may create/delete only one owned non-production resource group and must never mutate an existing or production resource. |
| Maintenance API → coordinator state | A privileged request remains intent until coordinator-side scope/eligibility reauthorization and audited cadence CAS. |
| Three service-principal contexts → Azure/Fabric | Separate token caches and exact action sets prevent fixture, Job-control, and evidence-read authority from bleeding across live stages. |
| Job operator → publisher drill CLI → drill workspace | The operator may start a bounded Job, but only the publisher UAI may create/consume the expiring validation control. |
