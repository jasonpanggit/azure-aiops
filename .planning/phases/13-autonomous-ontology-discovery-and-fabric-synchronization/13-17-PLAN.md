<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Coordinator/API command → publisher worker | Non-writer processes request consequential work through durable data. |
| API rollback intake → publisher intake adapter | Caller intent is untrusted until current scope, target retention, and pointer ETag are revalidated under publisher identity. |
| Coordinator dispatch workspace → publisher worker | Coordinator owns immutable publish payload creation; publisher receives only publish due/claim/lease/status capabilities in the isolated workspace. |
| Publisher identity → OneLake/Fabric | The only authoritative writer crosses the managed-identity boundary. |
| Active pointer → five consumer families | One conditional update changes reader-visible ontology generation. |

| T13-G17-02 | Tampering | publish/rollback command | critical | mitigate | Content identity, immutable body, ETag status CAS, complete candidate/target validation. |
| T13-G17-03 | Tampering | pointer stale writer | critical | mitigate | Finite lease, monotonic fence, source/current/ETag rechecks, and independent-worker fault tests. |
