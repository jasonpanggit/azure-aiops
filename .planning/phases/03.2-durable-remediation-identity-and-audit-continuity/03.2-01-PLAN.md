<objective>
Implement Phase 03 deep-review Recommendation 1 (durable plan identity + decoupled execution/audit reads), covering CR-01 (plan identity is a hash of mutable evidence), CR-06 (unhandled AttributeError when plan_repository is None), and the audit-access half of WR-07. Derive live plan identity from stable facts only (canonical target ARM id, subscription, governed action family) per D-01, authorize single-execution reads/retries/cancels from the execution record's own immutable scope attributes rather than the continued existence of a regenerated plan per D-02, make the execution service fail closed instead of crashing when no plan repository is configured, and add read-only diagnostics for legacy records whose plan_id can no longer be resolved, without any broad data migration per D-04.

Purpose: A successful patch run currently erases its own audit trail the moment vulnerability evidence changes, because the plan's identity is a hash of that evidence. This silently orphans the decision/execution record, makes verification unreachable, and reports "not run yet" for a run that already changed a production host. This plan closes that specific reliability gap without touching retry accounting, verification scheduling, approval policy, or operator UI (Phases 03.3-03.6).
Output: Stable `opportunity_id`/`plan_id` derivation for both live action families; a `scope_attributes` field and legacy-compatible derivation on execution records; scope-attribute-based authorization for `get_execution`/`retry_execution`/`cancel_execution`; fail-closed `plan_repository_unavailable` handling in `execute`/`retry`/`plan_eligibility`; a diagnostics endpoint for orphaned/legacy executions; and a dedicated regression test proving execution/audit continuity survives evidence mutation and plan regeneration.
</objective>
