<objective>
Close the request-consistency half of WR-07: resolve exactly one `LiveRemediationPlanner`/`PlanRepository` view per request per D-03 so that plan-scope validation and execution construction can never observe two different generations within the same call. Builds on 03.2-01's stable plan identity and durable, scope-attribute-based execution authorization -- this plan only changes how the planner/repository singleton is resolved and cached, not identity or authorization.

Purpose: Today `hybrid_remediation()` builds a brand-new `LiveRemediationPlanner` (and a brand-new in-memory `PlanRepository`) on every call, with zero caching. Because the router's scope-validation path (`_get_scoped_plan` -> `_planner` -> `_require`) and the execution-construction path (`_execution_service_for_scope` -> `_planner_for_scope`) both call this same function independently within one HTTP request, they can end up looking at two different repository generations even though 03.2-01 already made `plan_id` itself stable.
Output: A directly unit-testable TTL-cache helper wired into `hybrid_remediation`, plus tests proving cross-path identity and correct cache expiry.
</objective>
