## Decisions Made

- Reused the exact `_HYBRID_VULNERABILITY_CACHE_TTL_SECONDS` constant for `hybrid_remediation`'s cache rather than introducing a second TTL constant, keeping cache-freshness behavior identical across the hybrid provider family.

## Deviations from Plan

None — plan executed exactly as written, including the exact `_ttl_cached_value` signature, cache-key shape, and closure structure specified in the plan's `<action>` block.

One test-construction adjustment (not a deviation from the plan's intent, just an implementation detail left to "the agent's discretion" by the plan): the integration test in Task 2 could not use a locally seeded ARG fixture directly (the local-seed credential kind is unsupported for the live ARG connection path `hybrid_network`/`hybrid_vulnerability` actually exercise), so `api.runtime.live_vulnerability_service` was monkeypatched to a lightweight fake returning an object with `freshness`/`asset_exposures()`, avoiding any live Azure/ARG dependency while still exercising the real `hybrid_remediation`/`_ttl_cached_value` caching path end-to-end.

## Issues Encountered

- Initial attempt at the Task 2 integration test used `seed_local_environment(...)` + `AIOPS_RUNTIME_MODE=demo`, which failed because the seeded local-fixture credential (`kind="local_fixture"`) is not supported by `CredentialResolver.build()` (which requires `service_principal`) for the live ARG client path `hybrid_vulnerability`/`hybrid_network` traverse. Resolved by monkeypatching `api.runtime.live_vulnerability_service` directly so the test exercises `hybrid_remediation`'s caching behavior without needing a real or locally-seeded Azure credential.
