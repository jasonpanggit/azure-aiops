# Phase 03.8: Native Fabric IQ Adoption - Context

**Gathered:** 2026-09-14
**Status:** Ready for AI design and planning
**Source:** Deployed read-only Fabric IQ/Data Agent adoption audit

<domain>
## Phase Boundary

This phase converts the existing Fabric IQ-ready ontology, Data Agent items,
and governed specialist tools into measured native Fabric IQ consumption for
two initial use cases:

1. topology and blast-radius traversal;
2. policy and governance context.

It also activates curated Gold/Data Agent grounding through managed
authorization and measures whether native grounding improves answers over the
existing deterministic and OneLake-projection paths.

It does not move resource identity authority out of `InventoryReadPort`, allow
Fabric IQ or a model to authorize scope, replace deterministic checks, broaden
remediation authority, redesign pages, or publish page-specific Fabric
artifacts.
</domain>

<audit_baseline>
## Deployed Baseline

- The Fabric workspace contains two Data Agent items, one Ontology, one
  GraphModel, two Lakehouses, and two SQL endpoints.
- The deployed API has Fabric workspace and ontology configuration.
- `AIOPS_ENABLE_FABRIC_IQ=false`.
- `FABRIC_GOLD_GROUNDING_AGENT_ID` and `FABRIC_DELEGATED_TOKEN` are absent.
- Eight Foundry specialist names are configured, but Foundry prompt-agent
  availability is distinct from Fabric IQ usage.
- The three governed tools `fabric_iq_relationships`,
  `fabric_iq_topology`, and `fabric_iq_policy_context` are registered and
  optional for most specialists.
- The current `FabricIQToolAdapter` runtime binding calls the in-process
  OneLake ontology projection and stamps
  `source=onelake-ontology-projection`; it does not call native Fabric IQ.
- Application Insights contains zero Fabric IQ or Gold-grounding events in
  the last 30 days.
- The current live Gold-grounding evaluation baseline is intentionally
  degraded: groundedness mean 0.283, tool correctness 1.0, and deterministic
  fallback remains authoritative.
</audit_baseline>

<decisions>
## Implementation Decisions

### Authority and provenance

- `InventoryReadPort` remains the only resource identity authority.
- The API derives and enforces effective scope before any native Fabric IQ or
  Data Agent call.
- Native Fabric IQ results are enrichment evidence only and always carry
  exact native provenance, freshness, authorization, ontology/product
  generation, and bounded citation references.
- The existing OneLake ontology projection remains a separately named
  fallback and must never be labeled as native Fabric IQ.
- Deterministic findings remain available and authoritative when native
  services are disabled, empty, denied, slow, malformed, stale, or unavailable.

### Initial native use cases

- Start with topology/blast-radius traversal and policy/governance context.
- Do not enable every specialist or page at once.
- Native answers must cite stable ontology entities/relationships or curated
  Gold evidence visible within the caller's authorized scope.
- Unsupported or conflicting native evidence is qualified or rejected; it
  never silently overrides inventory identity or deterministic checks.

### Authentication and secrets

- Use managed identity and supported token exchange/delegation patterns.
- Do not commit, log, persist, or expose delegated access tokens.
- No browser-provided token becomes backend authority.
- Native Fabric IQ, Data Agent, Foundry, and OneLake identities remain
  distinguishable in audit and telemetry.

### Rollout and measurement

- Rollout is default-off, then shadow, then bounded canary, then explicitly
  approved enablement.
- A kill switch returns immediately to deterministic plus
  OneLake-projection fallback without deleting Fabric data, ontology, Gold,
  evaluation, or audit history.
- Measure native-call rate, successful/empty/denied/unavailable outcomes,
  latency, citation validity, scope violations blocked, fallback rate, cost,
  and answer-quality lift over the existing baseline.
- No promotion occurs without passing deterministic security/contract tests,
  an offline reference set, live canary evidence, and human review of
  disagreements.

### the agent's Discretion

- Exact native Fabric IQ REST/SDK client shape and internal interface names,
  provided first-party supported APIs are used.
- Exact evaluation sample size and thresholds, provided they are explicit,
  statistically interpretable, and compare the same questions/evidence across
  deterministic, OneLake-projection, and native arms.
- Whether Data Agent grounding is enabled in the same canary or a second
  canary step, provided native traversal is independently observable.
</decisions>

<deferred>
## Deferred Ideas

- Native Fabric IQ use for every specialist and every page.
- Autonomous relationship acceptance or production remediation.
- Replacing local orchestration, approval, evidence ledger, or deterministic
  policy checks with a managed agent.
- New Fabric ingestion or page-specific snapshot publication.
- Changes to the independent Phase 03.1 closeout evidence gates.
</deferred>
