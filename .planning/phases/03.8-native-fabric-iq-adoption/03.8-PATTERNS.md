## Non-Negotiable Boundary

- `InventoryReadPort` remains the sole resource identity/lifecycle authority.
- Effective scope is derived by the API before either native provider is called and is rechecked atomically after the call.
- Provider output is enrichment evidence only. It has `identity_authority=False` and cannot create identity, widen scope, reverse deterministic policy, authorize mutation, or suppress deterministic findings.
- Exact source names are immutable:
  - `fabric-iq` only for an accepted response from the documented native ontology MCP/toolbox surface;
  - `fabric-data-agent-gold` only for accepted published Data Agent evidence;
  - `onelake-ontology-projection` only for the existing in-process projection.
- Disabled, denied, empty, partial, stale, timed out, malformed, conflicting, or unavailable optional providers must preserve the deterministic response and select an explicit, separately labeled fallback.
- All Phase 03.8 tools remain read-only. Do not add a mutation tool, publisher capability, autonomous relationship acceptance, remediation authority, or page-specific Fabric publication.
- Tokens, authorization headers, raw provider payloads, prompts containing credentials, and credential objects must never enter models, caches, logs, metrics, ledgers, Terraform state, evaluation fixtures, or retained live reports.
- Do not treat `TopologyOntologyBinder.bind()` as a traversal call. It publishes a definition; it does not prove native Fabric IQ consumption.

Implement outbound lifecycle in this order:

1. open bounded `httpx.AsyncClient` session and acquire an ephemeral workload token;
2. `initialize`;
3. initialized notification when required by negotiated protocol;
4. `tools/list`;
5. discover the single question tool and its input property—do not hard-code either;
6. `tools/call`;
7. if task-backed, poll `tasks/get` under the same outer deadline;
8. on caller cancellation/deadline, best-effort `tasks/cancel`;
9. close the session and dispose header/token references.

## Shared Patterns

### Authentication and authorization

**Sources:** `src/api/auth.py:28-279`, `src/api/dependencies.py:219-286`, `src/api/rbac.py:205-300`, `src/intelligence/inventory/read_port.py:10-112`

- Authenticate first.
- Derive local effective scope with `Authorizer.effective_scope`.
- Resolve inventory identity before provider/token work.
- Keep downstream provider authorization distinct from local authorization.
- Reauthorize provider output after retrieval.
- Keep browser/gateway tokens out of `Principal` and all domain models.

### Error and outcome handling

Use closed, low-cardinality outcomes:

`ok`, `empty`, `partial`, `denied`, `stale`, `timeout`, `malformed`,
`conflicting`, `unavailable`, and `cancelled`.

Only bounded transient failures are retryable. Convert provider failures to explicit optional-provider outcomes; never swallow deterministic findings. Error logs contain provider, operation, attempt, exception class/closed reason, and correlation ID—not raw provider bodies or credentials.

### Provenance and generation

The current runtime test at `tests/test_api_runtime.py:1090-1110` is the preservation gate for projection naming. Extend it to assert two distinct providers and that only the native provider can produce `fabric-iq`.

Follow generation-qualified validation from
`src/fabric_pipelines/vulnerability_pipeline.py:1158-1180`: every accepted row/fact must belong to the selected generation, and mixed-generation material is rejected before publication/display.

### Durable audit and no mutation

`src/operations/autonomous_investigation.py:1108-1134` deep-copies historical ledger projections rather than rewriting stored evidence. Preserve this one-way history rule.

The existing ledger writes are best-effort (`:1160-1176`), which is insufficient for displayed shadow/canary native evidence. Phase 03.8 must add a display gate that confirms durable persistence; on failure, serve deterministic-only and emit a critical audit gap.

Keep `tests/test_mcp_protocol.py:48-90` as a read-only boundary test. Unknown or mutation tools remain denied, specialist catalogs remain exact, and caller-supplied `scope` is not part of tool schemas.

### Separate API and evaluation environments

Use the locked `api` extra for production/native adapters and the isolated `eval` extra for Phoenix. Keep `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` in targeted pytest commands. Phoenix remains loopback/offline and receives sanitized spans only.
