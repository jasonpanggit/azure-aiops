## Hard Validation Rules

1. Phase 03.8 makes no file or cloud mutation until Phases 03.7, 11, and
   13 each have every expected summary and verification front matter exactly
   `status: passed`. A waiver, deferral, conditional acceptance,
   `human_needed`, `gaps_found`, or any other status fails closed.
2. Plans 01 and 15 split contract-first work below the ten-file threshold.
3. The OBO decision writes one exact branch plus selected/non-selected file
   sets and baseline digests. Plan 03 contains complete executable gateway and
   API-side branches, executes only the selected branch, and proves every
   non-selected file remains byte-identical. No downstream replan or assumed
   request handle exists.
4. Every cloud mutation uses the same mechanical chain: create one concrete
   Terraform saved plan, normalize and hash its exact actions/resources/
   non-secret config, sign those hashes, re-run `cloud-change-gate`, apply only
   that saved-plan path, and retain immutable post-apply evidence. Generic or
   regenerated apply is forbidden.
5. Pre-provision readiness in Plan 16 covers tenant/region/capacity,
   network/private-link/DNS/egress, and Data Agent UAI/workspace/source
   prerequisites only. Plan 28 produces post-apply connection/toolbox
   readiness after the exact signed control-plane apply and before Plan 04
   native-shape approval.
6. Rollout/telemetry are applied by signed Plans 29-30 before Shadow 01.
   Off/kill tests
   spy on provider invocation and display projection; both counts must be zero.
   Child spans enclose real native, Data Agent, projection, validation,
   fallback, display, and ledger operations.
7. Human labels/signatures are created only in Plan 17 checkpoints. Autonomous
   plans can scaffold schemas/cases but must retain `UNLABELED`/HOLD.
8. Plan 11 alone creates `offline-88.release-01.json`. Plan 10 exercises the
   evaluator only with pytest temporary output paths.
9. Before Shadow 01, Plan 11 builds/pushes and resolves one immutable ACR API
   digest from the complete committed runtime tree and Plan 09 config. Plan 31
   signs image, predecessor, source, config, and exact Terraform saved-plan
   digests. Plan 32 applies that plan under an off interlock, verifies deployed
   digest plus `/health` and `/ready`, and only then creates the Shadow start.
10. Each 7/14-day stage is deploy/start → external wait → resume validation.
   No executor remains active and no aged evidence is synthesized.
11. Canary 1 exit review and Canary 2 authorization are separate signed files.
12. Plan 30 produces a distinct immutable off-state kill/rollback-control
   rehearsal before Canary 1 planning; it does not replace Plan 26's final
   live rollback after Canary 2.
13. Plan 12 combines current cost review with Canary 1 saved-plan preparation;
    Plan 22 combines Canary 1 exit review with Canary 2 saved-plan preparation.
    Canary signatures, saved-plan applies, and external waits remain separate.
14. Plan 26 is apply/start → external-wait checkpoint → resume/seal. Its two
    consecutive 15-minute post-rollback windows must each independently prove
    zero provider/display calls from provider timestamps.
15. After rollback, Plan 14 can sign only `HOLD_OFF`. Re-entry requires new
   `reentry-shadow-01` artifacts, another evidence interval, human approval,
   and replanning.
16. Every report, saved-plan, approval, and apply-receipt path in
   `03.8-PATTERNS.md` is create-if-absent and has one sole producer.
