<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Remediation API | Approver input, scope, reason, expiry, and action version cross from an untrusted client into server validation. |
| API -> Remediation planner/repository | Decision route reads generated recommendations and appends auditable approval decisions. |
| Scoped evidence -> UI/Copilot snapshot | Mixed-source evidence and identifiers are exposed to the browser and Copilot context under current authorization scope. |
| Documentation/schema -> ontology projection | Schema drift can cause graph consumers to misinterpret approval state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | `/remediation-plans/{plan_id}/decisions` | high | mitigate | Derive approver identity server-side from existing API dependency/auth context; never trust client-supplied identity. |
| T-02-02 | Tampering | action_version/scope/reason payload | high | mitigate | Require action_version match against current generated plan, require non-empty reason, persist exact request scope, and reject out-of-scope plans. |
| T-02-03 | Repudiation | approval decision records | high | mitigate | Store immutable append-only decision records with identity, timestamp, reason, scope, action version, expiry, and revalidation details. |
| T-02-04 | Information Disclosure | Remediation page evidence/Copilot snapshot | high | mitigate | Preserve existing scoped API filtering, avoid unvalidated non-ARM IDs in selected_resources, and keep source identifiers inside evidence rows. |
| T-02-05 | Denial of Service | provider fan-in on Remediation page | medium | mitigate | Treat individual provider failures as source warnings and render available bounded data; preserve pagination limits. |
| T-02-06 | Elevation of Privilege | approval vs execution boundary | critical | mitigate | Do not introduce execution/job/rollback invocation routes; approvals only create decision records and readiness state. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs are planned; if executor adds one, stop and run the package-legitimacy gate first. |
</threat_model>
