<objective>
Record in the semantic graph which Defender evidence each remediation plan targets, using predicates that describe intent rather than outcome, and publish those facts through the same path that already publishes approval decisions.

Purpose: The graph is how the platform answers whether an approved remediation later cleared the Defender assessment. That question is only answerable if the plan-to-evidence link exists and if the predicate never overstates what approval proves.
Output: Four new relationship types, a projection that emits them, a publication path, aligned documentation, and drift tests.
</objective>

## Fixed Predicate Names

Research assumption A1 left these open. The planner decision, recorded in `02-02-PLAN.md`, fixes them here:

Subject | Predicate | Object
--- | --- | ---
`RemediationPlan` | `addressesFinding` | `DefenderAssessment`
`RemediationPlan` | `addressesAlert` | `SecurityAlert`
`RemediationPlan` | `breaksAttackPath` | `AttackPath`
`RemediationPlan` | `improvesControl` | `SecureScoreControl`

Per D-26, resolution verbs are forbidden. A plan that exists, or is even approved, has not fixed anything; only post-change evidence in Phase 3 can support that claim. All four entity types and the `RemediationPlan` type already exist in the registries, so this plan adds relationships only, satisfying D-24.
