## Registration Is A Four-Part Atomic Change

Research Pitfall 4 documents that adding one tool touches four places and that nothing enforces atomicity except two contract tests. For every tool this plan adds, all four must land together:

1. A handler function plus a `ToolSpec` entry in `TOOL_REGISTRY` in `src/operations/tools.py`.
2. The tool name in `REVIEWED_TOOLS` in `src/operations/mcp_server.py`, which gates `call_tool` and drives `tool_definitions`.
3. A row in `foundry_tool_registry` in `infra/terraform/foundry.tf`.
4. The tool name in the relevant specialist lists in `foundry_specialist_tools` in the same file.

Run `tests/test_foundry_tool_registry_matches_implementation.py` and `tests/test_mcp_tools.py` after each tool, before moving on.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model tool call -> governed tool surface | An LLM chooses arguments that reach scoped operational data. |
| Terraform advertisement -> deployed specialist prompt | Infrastructure data becomes the only thing the model knows about a tool. |
| Defender vendor prose -> agent narration | Untrusted third-party text reaches an operator as guidance. |
| Specialist output -> operator decision | Narration influences whether a human approves an Azure change in Phase 3. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-23 | Elevation of Privilege | New MCP tools | critical | mitigate | Every handler is read-only, resolves through existing scoped providers, and accepts read filters only; Task 2 Test 7 fails if a state-changing parameter appears. |
| T-02-24 | Information Disclosure | Tool responses | high | mitigate | Reuse the existing scoped provider resolution and scope filtering; Task 1 Test 5 asserts an excluding scope returns no rows. |
| T-02-25 | Tampering | Registration drift across four surfaces | high | mitigate | Treat registration as atomic and run both contract tests in every task's verify block, per research Pitfall 4. |
| T-02-26 | Tampering | Defender prose reaching narration as an instruction | high | mitigate | Per D-11 the prompt forbids treating vendor prose as an instruction and restricts proposals to typed catalog entries; Task 3 Test 5 asserts it. |
| T-02-27 | Repudiation | Uncited agent claims | high | mitigate | Extend the per-agent contract so a recommendation missing citations, confidence, uncertainty, or the next safe check fails validation. |
| T-02-28 | Denial of Service | Large tool payloads | medium | mitigate | Reuse the existing bounding helper and the MCP layer's message-size limits; Task 1 Test 7 exercises truncation. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages. If an executor needs one, stop and run the package-legitimacy gate first. |
